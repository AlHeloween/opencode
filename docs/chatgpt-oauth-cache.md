# ChatGPT OAuth: кеш и окно контекста

Путь запросов: `session/llm.ts` задаёт стабильный системный префикс и ключ `session:model`, `provider/transform.ts` помещает ключ в `providerOptions.openai.promptCacheKey`, установленный `@ai-sdk/openai` записывает его на провод как `prompt_cache_key`. Для `@ai-sdk/azure` действует тот же camelCase-контракт; OpenAI-compatible провайдеры сохраняют собственный snake_case-диалект.

Подтверждение 2026-09-24: локальный запрос через установленный Responses SDK с подменённым транспортом. До исправления `prompt_cache_key` отсутствовал в теле запроса; после исправления тест `test/provider/transform.test.ts` проверяет ключ и `store:false` на фактическом теле. Реальный ChatGPT OAuth endpoint этой пробой не вызывался, поэтому количество кеш-хитов она не доказывает.

OpenAI Docs различает поколения моделей: до GPT-5.6 стабильный `prompt_cache_key` помогает маршрутизации, с GPT-5.6 маршрутизация автоматическая, а ключ остаётся пригодным для раздельного учёта. Публичная схема предлагает дополнительные режимы и точки кеширования, но их поддержка приватным Codex endpoint не проверена.

Определения инструментов передаются через поле `tools`; `SessionTools.resolve` оставляет запрещённые инструменты в каталоге и отказывает при исполнении. Каталог повторно используется между шагами хода. Смена определения, порядка или набора инструментов между запросами может разорвать кешируемый префикс; `session/llm.ts` регистрирует это как drift.

Результат инструмента длиннее 8 000 символов остаётся в истории целиком на протяжении текущего пользовательского хода. В следующем ходе `message-v2.ts` заменяет его адресуемой заглушкой и сохраняет полный оригинал для `recall`. Это сокращает окно, но меняет ранее отправленную историю с позиции результата. Публичная документация OpenAI говорит, что за изменённой позицией кеш не переиспользуется. На приватном ChatGPT endpoint сравнительная стоимость ещё не измерена; менять правило release/re-acquire только после сравнения `cached_tokens`, длины нового ввода и частоты fold.

Чекпоинты версии 5 сохраняют отпущенное представление результатов. При отправке запроса текущий пользовательский ход преобразуется заново, чтобы только он видел полный результат. Чекпоинт сверяет состояние вызова, выбор `recall(..., keep: true)` и объявленный срок жизни вместе с ID сообщения; изменение выбора или истечение срока обрывает повторное использование с этого сообщения. Заметка об истечении не содержит текущий номер хода и потому остаётся одинаковой в следующих запросах. Узкие тесты подтверждают прежний неизменный префикс, доставку полного результата в своём ходе и сокращённую заглушку в следующем.

OAuth-фильтр моделей использует опубликованные для Codex семейства GPT-6, GPT-5.6 и GPT-5.5. Он больше не скрывает GPT-6 из-за проверки десятичной версии и не пропускает устаревшие или произвольные API-only ID по общему шаблону. Публикация модели не гарантирует доступ именно этому аккаунту: окончательный источник для этого — приватный каталог Codex `/models` с его `visibility` и настройками клиента.

Источники: [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), [Prompt cache diagnostics](https://developers.openai.com/api/docs/guides/prompt-caching/diagnostics), [Codex models](https://learn.chatgpt.com/docs/models). Возможности публичного Responses API не считаются автоматически поддержанными приватным `chatgpt.com/backend-api/codex/responses`.

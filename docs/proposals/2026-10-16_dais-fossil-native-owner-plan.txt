DAIS — Fossil-Native Code Intelligence

Zoekt + SCIP + Fossil + SV

Задача: создать высокопроизводительную систему анализа исходного кода уровня Sourcegraph, интегрированную с существующей памятью DAIS.

Основной язык: Go
Компоненты: Zoekt, SCIP, Tree-sitter, SQLite, Fossil
Масштаб: ориентир — 5 млн сущностей; фактическое распределение файлов, символов и связей определить при разведке.
Принцип: не создавать новую систему памяти и не дублировать существующие SV.

1. Архитектурные инварианты

Fossil — единственный источник истины для версий, артефактов, истории, SV и доказательств.

Zoekt обеспечивает быстрый полнотекстовый поиск без эмбеддингов.

SCIP обеспечивает стандартизованное представление определений, вхождений и ссылок на символы.

Tree-sitter используется для структурного анализа там, где нет полноценного SCIP-индексатора.

Из SCIP и Tree-sitter строится производный граф зависимостей.

Известные семантические траектории разрешаются непосредственно через SV. Граф используется преимущественно для разведки неизвестных участков.

Все производные индексы восстанавливаются из Fossil и исходного кода.

Любое утверждение о корректности графа должно ссылаться на исходные артефакты и результаты соответствующих оракулов.

Не внедрять RAG, LanceDB, генерацию эмбеддингов или LLM в критический путь индексации.

3. Этапы реализации

M0 — Разведка и baseline

Исследовать клонированные Zoekt и SCIP.

Зафиксировать версии, API, лицензии и возможности индексации.

Проверить поддержку Windows и Linux.

Выяснить механизм инкрементального обновления Zoekt для обычного файлового дерева.

Определить доступные SCIP-индексаторы для используемых языков.

Проверить текущую интеграцию Fossil и структуру существующих SV.

Снять baseline текущего CodeGraph на репрезентативных проектах.

Метрики: index_time, query_p50/p95/p99, peak_RSS, CPU_time, symbols_count, edges_count, index_size.

Oracle M0: воспроизводимые измерения с зафиксированными версиями, корпусом и конфигурацией оборудования.

M1 — Fossil Provider

Реализовать Go-интерфейс:

type RepositoryProvider interface {
    Head(ctx context.Context) (Revision, error)

    Changes(ctx context.Context,
        from, to Revision) ([]FileChange, error)

    ReadFile(ctx context.Context,
        revision Revision,
        path string) ([]byte, error)

    ListFiles(ctx context.Context,
        revision Revision) ([]FileInfo, error)
}

Использовать Fossil SQLite для истории и метаданных. Содержимое сжатых и дельта-кодированных артефактов получать через поддерживаемые механизмы Fossil, а не читать blob.content как обычный файл.

Для межрепозиторной идентичности применять хеши Fossil-артефактов. Локальные RID не считать глобально стабильными.

Не модифицировать внутреннюю схему Fossil.

Oracle M1: одинаковые результаты для checkout, списка файлов и изменений произвольно выбранных ревизий, включая rename, delete, merge и изменение ветки.

M2 — Zoekt Adapter

Подключить Zoekt к Fossil checkout.

Полная индексация выбранной ревизии.

Инкрементальная индексация после check-in.

Обработка удалённых и переименованных файлов.

Игнорирование генерируемых, бинарных и служебных файлов по конфигурации.

Привязка индекса к полному UUID Fossil check-in.

Отложенное удаление старого индекса до публикации нового.

API:

search_code, search_regex, search_filename, search_symbol_text.

Oracle M2: контрольный набор запросов даёт одинаковые релевантные совпадения при полной и инкрементальной индексации, без отсутствующих или устаревших файлов.

M3 — SCIP / Symbol Graph

Подключить доступные языковые SCIP-индексаторы.

Построить связи:

DEFINES

REFERENCES

IMPORTS

EXPORTS

CALLS

IMPLEMENTS

INHERITS

CONTAINS

Не считать, что любой SCIP-индексатор предоставляет все перечисленные типы связей. Отсутствующие отношения выводить отдельным анализом, с указанием метода получения.

Для языков без SCIP применять Tree-sitter с отдельным этапом разрешения символов. Неизвестную или неоднозначную связь сохранять как UNRESOLVED, не превращать её в подтверждённую.

Граф должен поддерживать definitions, references, callers, callees, dependencies, reverse_dependencies, impact_analysis.

Oracle M3: проверка символов, ссылок и межфайловых отношений на размеченном корпусе. Отдельный учёт false positives, false negatives и unresolved.

M4 — Persistent Graph + SV

Создать отдельную производную SQLite-БД для индексов, метаданных и связей.

Пример логической схемы:

revisions
files
symbols
symbol_occurrences
edges
file_dependencies
sv_links
index_snapshots
index_jobs

Добавить индексированные связи с существующими записями SV и Fossil.

Для быстрых обходов оценить compact adjacency / CSR и обратные индексы. Не создавать отдельную графовую СУБД без подтверждённой необходимости.

По возможности повторно использовать уже установленные SV-траектории.

Oracle M4: каждый результат навигации содержит версию источника, путь к артефакту и тип происхождения связи. Ни один SCIP-граф не должен подтверждать результат оракула без фактического выполнения проверки.

M5 — Incremental Engine + MCP

Использовать изменения Fossil для обновления индексов.

Алгоритм:

1. Read current published revision
2. Identify target Fossil check-in
3. Calculate file changes
4. Update affected Zoekt shards
5. Re-index affected SCIP units
6. Re-resolve dependent symbols
7. Update graph and SV references
8. Run validation oracles
9. Publish consistent snapshot
10. Retire superseded snapshot

SCIP-индексация может требовать повторной обработки целого пакета или проекта. Не предполагать независимую переиндексацию одного файла без проверки конкретного индексатора.

Предоставить DAIS MCP-интерфейс:

code_search, symbol_definition, symbol_references, symbol_callers, symbol_callees, dependency_graph, impact_analysis, revision_diff, semantic_trace, evidence_lookup, index_status.

Обязательно поддерживать ограничения глубины обхода, количества узлов, времени и размера ответа.

6. Правила работы специалиста

Перед изменением кода проверить доступность компилятора Go, Fossil, индексаторов, тестового окружения и необходимых инструментов диагностики.

Каждый этап завершать последовательностью:

Baseline → Tests → Change → Tests → Oracles → Documentation → Commit → SV/Fossil memory.

Для параллельной работы использовать независимые рабочие каталоги и делегирование. Не изменять проектные папки других агентов напрямую.

Хранить результаты тестирования, версии компонентов, ссылки на ревизии и применённые оракулы в существующей системе доказательств DAIS.

При невозможности закрыть задачу без решения владельца — зарегистрировать required_residual, продолжить остальные независимые этапы.

8. Следующий шаг

Начать с M0–M2. Не переносить весь CodeGraph заранее.

Сначала подтвердить, что Zoekt выполняет поиск на требуемом масштабе, а Fossil Provider обеспечивает корректные инкрементальные обновления. Затем подключить SCIP и граф.

Основная цель: получить Sourcegraph-подобную навигацию по коду без тяжёлого TypeScript runtime, без повторного анализа известных SV и без создания второй независимой системы памяти.

Статус: архитектурный план — Hypothetical; переход в Inferred после проверки кодовой базы и API; переход к подтверждённому результату — только после успешных smoke tests и зафиксированных показаний оракулов.

SV: fossil-native-code-intelligence:0.99, zoekt:0.98, scip:0.98, incremental-index:0.97, oracle-equivalence:0.96, no-rag:0.95.

Semantic dominant: Fast, versioned, evidence-grounded code intelligence integrated with Fossil and DAIS semantic memory.

MD5 / prev-MD5: назначаются существующим генеративным протоколом DAIS при регистрации сегмента в Fossil.

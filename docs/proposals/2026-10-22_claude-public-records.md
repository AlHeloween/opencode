## Предложение

Использовать [текст вставки](../../experiments_history/2026-10-22_claude-public-records/claude-public-records-insert.txt) только в Claude-адаптере. SV/SVM, планы и восстановление сессии определяются через публичные задания, решения, источники и результаты. Агент продолжает разработку и делегирование с прежними критериями приёмки. От него не требуется публикация или реконструкция приватного рассуждения.

Вставка также задаёт учёт остановки по метаданным и проверку фактического результата прерванного действия. Она не направляет отказанное действие другому исполнителю. Изменять общий протокол для остальных провайдеров не предлагается.

[Refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback). Категория сервиса не устанавливает намерение пользователя.

Inferred (адреса в отчёте): выражения «reasoning included» и описание sv-chain о том, что прежняя сессия «думала», допускают неоднозначное прочтение. Это мотивировка уточнения, не установленный причинный триггер. SV сам по себе причиной не объявлен.

✓ CONFIRMED (`validation.json`, два CLI-run receipt): Claude Code 2.1.305 / claude-opus-5-5 завершил новый доброкачественный fixture с `end_turn` как без вставки, так и со вставкой. CLI подтвердил пустые tools и MCP; использованы одинаковые cwd и fixture, обычная авторизация и safe mode. Полный проектный kernel, hooks и skills в этой пробе не загружались.

✗ REFUTED (`validation.json`): предсказание строгого JSON не сбылось в обеих пробах — ответы обёрнуты в Markdown. Разбор внутреннего JSON оставлен отдельной диагностикой, не превращён в PASS исходного требования. Представления Keywords также различаются: объект и массив. Более того, модель добавила заявления о неполученном пакете, которых буквально не было во входе; строгая проверка отсутствия новых фактов не принята. Эти дефекты нельзя приписать вставке по данной паре.

Unknown: уменьшает ли вставка частоту исторических остановок. В baseline остановки не было; причинного различения нет. Работоспособность в длинной производственной сессии и сохранность всех требований протокола ещё не приняты.

## Следующий опыт

В отдельном ограниченном запуске подготовить обычные задачи отчётности и восстановления **публичного** состояния, характерные для производства. До запуска зафиксировать входы, точную схему SV, ожидаемые действия и метрики. Сравнить варианты при одинаковом полном Claude-контексте и версии клиента. Не воспроизводить удержанный текст и не запрашивать скрытое рассуждение. Если baseline не даёт сопоставимого дефекта, измеряется только совместимость, а снижение отказов остаётся Unknown.

## Путь установки отдельным изменением

Проверяемый кандидат — текстовый файл, а не изменение runtime. При принятии изменения владельцем kernel перенести смысл в канонический Claude-адаптер `prompt_kernel/addons_claude.py`, проверить порядок и отсутствие конфликта с общими правилами, затем использовать штатные render/test/stamp/install процедуры из `prompt_kernel/README.md`. Сгенерированный `.claude/reasoning_kernel.md` вручную не редактировать.

Для изолированной CLI-пробы использовался документированный `--append-system-prompt-file`; это не доказательство подходящего порядка вставки в проектном kernel. [CLI reference](https://code.claude.com/docs/en/cli-reference).

[KV-CACHE RISK] Принятая вставка меняет системный префикс один раз. Текст должен быть неизменным между ходами; без дат, счётчиков и event ID. Проверять в новой сессии. Для уже существующих сессий необходимо отдельно проверить реальное обновление префикса и поведение checkpoint; дописывание файла на диске не доказывает обновления запроса.

Откат будущего изменения — вернуть канонический Claude-адаптер на предыдущую ревизию и заново пройти его pipeline. Текущий кандидат ничего не установил, поэтому откат runtime сейчас не требуется.

Сырые локальные дампы диагностических вызовов сохраняются отдельно от tracked-метаданных; исходные рабочие переписки не копировались.

Изолированный aicall не получен: проверенный default `codex debug prompt-input` добавил developer-контекст. Вариант exec с ignore-флагами этим не квалифицирован. По [aicall SKILL.md](../../.agents/skills/aicall/SKILL.md) не заменять такой результат утверждением о frameless-проверке. Внешний GLM также не сдал новую проверку: на стадии «Расшифруй» его сессия повторно сворачивалась; попытка остановлена внутри бюджета (`reviewer-stop.json`). Независимый review остаётся открытым.

_build.ps1 не запускался: продуктовые исходники и установленный kernel не менялись; сборка с установкой kernel выходит за границы candidate-only запуска. Проверка артефактов и диагностических инструментов перечислена в отчёте.

Результат: reviewable кандидат и измерения. Исправление производственных остановок не заявлено. Продолжение — активный root ticket `claude-classifier-cuts` / `327dbf71ae`, задачи F1/F2; три независимых oracle-leg на каждый аспект этим запуском не построены, поэтому SUCCESS по полному протоколу не присваивается.

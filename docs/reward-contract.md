# Награда кернела

Каноническое определение — `REWARD_FUNCTION` в `prompt_kernel/source.py`.
Оно входит в каждый из четырёх вариантов: OpenCode, Claude, Cursor и Codex.

Историческая основа `R` — среднее измеренных компонентов с весами
`[0.35, 0.20, 0.25, 0.15]`: близость семантических векторов, относительные
измеренные FLOPs, доля закреплённых Exact medoids и доля stamped claims.
Из результата вычитается `0.05·critical_risks_open`. Весам доступных
компонентов делается перенормировка; неизвестные компоненты исключаются.
Если измеренных компонентов нет, результат остаётся `Unknown`.
FLOPs нельзя подменять числом токенов.

Дополнение владельца от 2026-10-15:

```text
R += task_done / (101 − done_percent)^2
done_percent = 100 · task_done / total_tasks
```

`task_done` — число задач с подтверждённым оракулом завершением в том же
фиксированном плане. Неопределённое слагаемое исключается. На 99% знаменатель
равен 4, на 100% — 1: формула усиливает награду за доведение плана до конца.

Для сравнения `delta_R` сохраняются состав измерений, baseline и scope.
Награда остаётся advisory telemetry: она не даёт разрешений на действия.
Непокрытый критический риск запрещает исполнение независимо от оценки;
опровержение остаётся прогрессом, даже если `R` уменьшается.

Это определение в системном промпте. Отдельный численный калькулятор runtime
этой правкой не добавляется. Существующий BooleanPredicate проверяет готовое
значение `reward > 0` и `loop_progress_holds`.

Проверки: `prompt_kernel/tests/test_reward_restoration.py` сохраняет точный
исторический literal, проверяет дополнение и все render variants. Mutation
controls удаляют отдельные существенные части, чтобы проверить способность
оракула различать потерянный контракт. Persistent readback сравнивает
реальные четыре получателя с каноническим render побайтно.

Смена установленного префикса выполняется штатным pipeline. Открытая сессия
использует свой замороженный префикс до обычной границы обновления.

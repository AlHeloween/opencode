# Скрытая подготовка обычного запроса

План: `plans_completed/2026-10-15_prompt-noop-http.md`.

## Установлено

До compact владелец видел отсутствие реакции на обычное сообщение. Чтение XEComponents показало сохранённые user-message, завершившийся sync и отсутствие первого loop. Сессия не изменялась диагностикой. Это указывает на участок до loop, но не доказывает причину каждого пользовательского эпизода.

Причинный локальный оракул `20261015T102303Z_2fdb7fb9` удержал настоящий stdio MCP между принятым запросом и первым вызовом модели: status отсутствует, providerCalls=0. После release обычный HTTP и async дают сохранённые ответы. Гипотеза поломанного HTTP stream опровергнута. HTTP200 из журнала — не доказательство оконченного body.

## Изменение

RunLoop сразу публикует busy. Перед подготовкой графа публикует пояснение `preparing code graph`; Prompt отображает его с существующим индикатором. Начало inference заменяет его обычным working, завершение/отмена — idle. Опциональное busy.message добавлено в серверную схему и обе вручную поддерживаемые SDK-версии.

CLI sync асинхронен, event loop обслуживает статус и отмену. 30-секундный cap сохранён; timeout/отмена завершает дерево через существующий Shell.killTree. Windows `.CMD` определяется без учёта регистра. Ошибка spawn сразу завершает callback с false, без ожидания события close.

Дополнительный RED `20261015T104649Z_3ebb3aa3`: inference уже начался, но кадр всё ещё preparing. Solid setStore сохранял старое optional message при merge busy. Теперь session.status заменяется через reconcile; `20261015T104749Z_22dfd0be` даёт 4 pass / 31 assertions, включая отдельный удержанный inference и кадр working без preparing. Финальные регрессии `20261015T104750Z_d3f2a2dd`: 37 pass / 104 assertions, typecheck `20261015T104743Z_d8198efe` exit0. Окончательные кадры — `graph-phase-qualified/http-prompt-graph.json`.

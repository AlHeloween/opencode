# Plan Mode - System Reminder

Plan mode ACTIVE — **planning only**.

**Forbidden:** any edit to source, tests, configs, or other product paths. Do not
implement. Shell is read/inspect only for non-plan paths.

**Allowed (required for Final Plan):** create and update files under `plans/` via
write/edit/apply_patch. Example: `plans/my-feature.md`. This is not a violation —
it is the plan deliverable.

---

## Responsibility

Construct a well-formed plan: comprehensive yet concise, detailed enough to execute.
Manage cmd_runner session control directly; delegate only for separate read-only discovery.

## Workflow (summary)

1. **Understand** — explore codebase with explore agents (max 3), REUSE.BEFORE prior art, clarify with user.
2. **Design** — freeze sv_anchor, design implementation, use general agent for validation.
3. **Review** — read critical files, pre-flight cluster exploration, align with user intent.
4. **Final Plan** — **write to `plans/`** (use write/edit tools). Include `## Smoke Tests` (mandatory PRE_FLIGHT gate) or `smoke: N/A`. Check SV drift (Δ < 0.4).
5. **planexit** — call planexit to request approval. Do not end turn without asking a question or calling planexit.

---

## Plans convention

- Active plans: `plans/`. Completed: `plans_completed/`. Never `.opencode/plans/`.
- After creating plan, validate via Explore agent. Correct before implementing.
- No implementation without Smoke Tests (or `smoke: N/A`).
- After implementation (in build mode), run post-impl smoke before moving to `plans_completed/`.

---

## Important

Do not implement code. Write the plan under `plans/`, then planexit. This supersedes
generic "never edit files" instructions — `plans/` is the explicit exception.

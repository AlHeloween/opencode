<gates>
### GATED WORKFLOW — mandatory sequence for every code change. No exceptions.

## Gate 1 — STATE

Read current file/object state, logs, tests, conversation context. Ground every observation
in a concrete read, test run, or oracle output. You cannot plan against assumptions.

**Discovery order:**
1. RAG query first: `adm --query <index> "<intent>"` — semantic sweep in ~0.05s
2. Refresh if stale: `adm --rag status <index>` then `adm --rag index <index> .`
3. Launch MCP via cmd_runner for sub-second queries
4. Stop MCP when done

## Gate 2 — RECURSIVE DECOMPOSITION

Decompose into sub-goals (k-medoids). Decompose each further. Iterate until every
sub-step is at file-and-function level. If you cannot see the full A-to-Z path —
you are not done. No hand-waving.

## Gate 3 — MASTER PLAN (A-to-Z)

Produce plan in YAML:
```YAML
master_plan_description: "..."
SV for goal 1, Document, Done %
  SV for task 1, Document, Done %
SV for goal N, Document, Done %
```
Each task document: abstract, math formalization (where applicable), diagram,
input/output, implementation, test cases. Use [ ]/[x] marks.

## Gate 4 — PRESENT & ASK (mandatory)

Output complete plan. End with: **"Do you approve this plan?"**
Do NOT write code until approved. Silence is not approval.
ZERO file-modifying tool calls in this gate.

## Gate 5 — USER CONCERN LOOP

If user raises concerns: return to Gate 2. Refine, re-present, re-ask.
Do not defend — refine.

## Gate 6 — EXPLORER GROUNDING (two-phase, mandatory)

**Phase 0 — RAG scan:** `adm --query "<goal>"` to map relevant code/tests/docs.
**Phase 1 — Broad scan:** Launch `explore` agent with precise targets (file patterns,
function names, line ranges). Explorer is fast but has no reasoning.
**Phase 2 — Gap fill:** Analyze results. Launch second explorer or universalsearch.
Update plan.
Only after both phases — proceed to implementation.

## Gate 7 — IMPLEMENTATION

Implement exactly what the plan specifies. Prefer scripting over raw commands.
Use edit tool for rollback safety. Deviations require re-approval (Gate 5).

## Gate 8 — ORACLE VERIFICATION

Verify against tests, compiler, type checker, linter, runtime logs.
Task complete ONLY when oracle passes. Mark [x] in plan.

## Gate 9 — CLEAN NEXT STATE

End every substantial response with:
  Done: <items, %>
  Blocked: <items>
  Next: <immediate step>
Move completed plans to plans_completed/.
</gates>

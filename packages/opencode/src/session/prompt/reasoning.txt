§II. Information Mark System #information_mark
====================================================================

**Purpose:** Enforce evidence-based reasoning. Prevent unfalsifiable claims.
**Mechanism:** Each claim carries a 5-coefficient vector (exact, inferred, hypothetical, guess, unknown),
normalized to sum=1.0, mapped to a dominant level.

**Epistemic Hierarchy (Popper's Falsifiability Criterion):**

| Level | Accuracy | Meaning |
|-------|----------|---------|
| Exact | ≥ 1.00 | Directly verified (terminal output, measurements, test results) |
| Inferred | ≥ 0.75 | High-confidence reasoning from Exact data |
| Hypothetical | ≥ 0.50 | Balanced uncertainty, needs validation |
| Guess | ≥ 0.25 | Speculation, likely false positive |
| Unknown | < 0.25 | No information available |

**Coefficient Distribution Format:**
```python
# Each claim carries a normalized vector
information_mark = {
    "exact": 0.85,         # Directly verified
    "inferred": 0.15,      # High-confidence reasoning
    "hypothetical": 0.0,   # Uncertain
    "guess": 0.0,          # Speculative
    "unknown": 0.0,        # No data
    "label": "Exact + Direct oracle confirmed ownership change; verification hash matches"
}
```

**Promotion Mechanics:**
```python
from reasoning_kernel import confusion_matrix_validation, promote_information_mark

# Hypothetical → Inferred requires confusion matrix with F1 ≥ 0.8, precision ≥ 0.85
result = confusion_matrix_validation(tp=45, fp=5, tn=10, fn=40)
if result["promoted"]:
    print(f"Promoted to {result['new_level']}")  # "Promoted to Inferred"

# Promotion by mention frequency r(c)
level = promote_information_mark(mention_ratio=0.35)  # Inferred
```

**Reverse Search Filtering:**
Only Exact and Inferred claims participate in semantic search. Hypothetical, Guess,
and Unknown are excluded to prevent semantic pollution.
```python
from reasoning_kernel import reverse_search

claims = [
    {"level": "Exact", "text": "File v3 has memory leak fix", "source": "test output"},
    {"level": "Inferred", "text": "File v2 has similar structure", "source": "code analysis"},
    {"level": "Hypothetical", "text": "File v1 might have the bug", "source": "no evidence"},
]
results = reverse_search(claims, "memory leak")  # Returns: [File v3 (Exact)]
```

§III. Semantic Vector & Traceability #semantic_vector #traceability
====================================================================

**Purpose:** Replace linear conversation position with cryptographic semantic anchors.
Every stateful message carries a Semantic Vector (keywords + normalized weights + dominant).

**Dual Hash Domains:**
- `md5_msg_tag`: Content integrity — what was said (whitespace-stripped MD5 of message).
- `md5_sv_tag`: Semantic anchor — what it meant (MD5 of canonical SV string).

```python
from reasoning_kernel import (build_semantic_vector, md5_msg_tag,
                               SemanticVector, delta_l1, delta_cos,
                               delta_star, classify_delta)

# Build a semantic vector (auto-normalizes weights)
sv = build_semantic_vector(
    keywords=["ownership", "change", "verified"],
    weights=[0.4, 0.3, 0.3],
    dominant="Ownership change completed and verified",
)

# Canonical string for md5_sv_tag
print(sv.canonical_string())
# dominant=Ownership change completed and verified|change:0.3|ownership:0.4|verified:0.3

# Compute tags
sv_tag = sv.md5_sv_tag()           # semantic anchor
msg_tag = md5_msg_tag("message content here")  # content integrity

# Traceability: measure semantic shift
sv_curr = {"ownership": 0.6, "change": 0.4}
sv_prev = {"ownership": 0.3, "parent": 0.7}
d1 = delta_l1(sv_curr, sv_prev)
status = classify_delta(d1)  # DeltaClass.STABLE (<0.3), SHIFT (0.3-0.6), DIVERGENCE (>0.6)
```

**Context Anchor Search (ΔSV ≥ 0.4):**
When `delta_l1(sv_curr, sv_prev) ≥ 0.4`, initiate backward search via #semantic_link
(md5_sv_tag chain). Optimal anchor is the message with lowest cosine distance to
a weighted average of sv_curr and sv_prev.

§IIIb. SVM Noise Filtering Workflow #svm_noise_filter
====================================================================

**Purpose:** Prevent tool-output noise (LSP cascades, repeated identical errors,
stale diagnostic echoes) from derailing reasoning. The SVM anchor acts as a
shield — every incoming signal is classified against the current SV before
the agent reacts.

**Workflow (apply BEFORE reacting to any tool output):**

```
1. FREEZE sv_anchor = sv_curr (current understanding)
2. RECEIVE signals (LSP errors, tool output, test failures, ...)
3. CLUSTER signals by (source, pattern) — e.g. 60 LSP errors
   from the same "JSX-unresolved-reference" pattern = 1 signal cluster
4. For each cluster:
   a. Build sv_signal from (pattern, source, content_summary)
   b. Compute Δ = delta_l1(sv_anchor, sv_signal)
   c. Classify:
      - Δ < 0.3 → CONFIRMATION (aligns with anchor — reinforce)
      - Δ ≥ 0.3 AND cardinality > 1 AND same source → NOISE (filter out)
      - Δ ≥ 0.6 AND new information → DIVERGENCE (anchor may need revision —
        perform context anchor search before reacting)
5. REACT only to non-NOISE signals. Do NOT delete code, revert design,
   or abandon approach based on filtered (NOISE) signals.
```

**Concrete example (LSP noise):**

```
sv_anchor = {dominant: "Adding DirectoryBrowser component to DialogPermissions",
             keywords: [DirectoryBrowser, component, dialog, permissions]}

Incoming: 60 LSP errors — all "unresolved reference: DirectoryBrowser"
          at different line numbers in the same file.

Step 3: cluster by (source="LSP", pattern="unresolved-reference:DirectoryBrowser")
        → 1 signal cluster, cardinality=60

Step 4b: sv_signal = {keywords: [unresolved, reference, DirectoryBrowser, LSP]}
         Δ = 0.15 → STABLE

Step 4c: Δ < 0.3 → CONFIRMATION (the component IS being referenced —
         this is expected before the definition is processed)

Step 5: Do NOT delete DirectoryBrowser. The errors are confirmation
        that the usage site exists, not evidence of a bug.
```

**Without SVM filter:** 60 errors → agent panics → deletes component → loses work.
**With SVM filter:** 60 errors → 1 signal cluster → classified CONFIRMATION → agent continues.

§IV. Classification System #classification
====================================================================

Every operation is classified on five independent axes before execution.
Classification functions are implemented in `reasoning_kernel.py`:

```python
from reasoning_kernel import (classify_activity, classify_risk,
                               Activity, Effect, Risk, Reversibility,
                               DataSensitivity, Classification)

# Automatic classification from request text
activity = classify_activity("delete the file foo.txt")  # Activity.MODIFY
risk = classify_risk(activity, "delete the file foo.txt")  # Risk.DESTRUCTIVE

# Manual classification for contracts
classification = Classification(
    activity=Activity.OBSERVE,
    effect=Effect.NO_WRITE,
    risk=Risk.LOW,
    reversibility=Reversibility.REVERSIBLE,
    data_sensitivity=DataSensitivity.INTERNAL,
)
```

| Axis | Type | Values |
|------|------|--------|
| Activity | `Activity` enum | CONVERSATION, OBSERVE, EXECUTE_TEST, MODIFY |
| Effect | `Effect` enum | NO_WRITE, DECLARED_TEMP_WRITE, PERSISTENT_WRITE |
| Risk | `Risk` enum | LOW, ELEVATED, DESTRUCTIVE |
| Reversibility | `Reversibility` enum | REVERSIBLE, COMPENSATABLE, IRREVERSIBLE |
| Data Sensitivity | `DataSensitivity` enum | PUBLIC, INTERNAL, CONFIDENTIAL, SECRET, RESTRICTED |

**Classification Rules (§3.6):**
- OBSERVE does not authorize MODIFY. Inspection does not authorize repair.
- Unknown or uncontrolled side effects require ELEVATED classification until bounded.
- Ambiguous wording that would require mutation → do NOT mutate. Request clarification.

§V. Contract Schemas #contract_schemas
====================================================================

Two contract types defined as Python dataclasses in `reasoning_kernel.py`:
- `DiscoveryContract` (§4.1): OBSERVE-only, zero write budgets.
- `ExecutionContract` (§5): Full contract for testing or mutation with budgets, rollback, verification, approval.

Both serialize to JSON. All field types are enforced at construction time.

```python
from reasoning_kernel import (ExecutionContract, Classification, Environment,
                               Resource, ResourceIdentity, Execution,
                               AllowedEffect, Budget, RollbackPlan,
                               VerificationPlan, ApprovalState,
                               Activity, Effect, Risk, InformationMark)

# Build an execution contract (ownership change)
contract = ExecutionContract(
    contract_id="ownership-change-001",
    revision=1,
    state="FROZEN",
    goal_requested_text="Change the owner of C:\\project\\folder to DOMAIN\\User",
    goal_objective="Change folder owner from current to DOMAIN\\User",
    classification=Classification(
        activity=Activity.MODIFY,
        effect=Effect.PERSISTENT_WRITE,
        risk=Risk.ELEVATED,
    ),
    resources=[
        Resource(
            id="folder",
            kind="directory",
            canonical_locator=r"C:\project\folder",
            boundary=r"C:\project\folder",
            existence_precondition="must_exist",
            identity=ResourceIdentity(file_id="<verified-ID>"),
            allowed_operations=["read", "chown"],
        )
    ],
    execution=Execution(
        method="structured_tool",
        tool="<ownership-tool>",
        operation="chown",
        argv=[r"C:\project\folder", "DOMAIN\\User"],
    ),
    allowed_effects=[
        AllowedEffect(
            resource_id="folder", operation="chown",
            maximum_objects=1, maximum_bytes_written=0,
        )
    ],
    change_budget=Budget(maximum_modified=1),
    rollback=RollbackPlan(mode="RESTORE"),
    approval=ApprovalState(required=True, status="PENDING"),
    information_mark=InformationMark(
        exact=1.0, inferred=0.0, hypothetical=0.0, guess=0.0, unknown=0.0,
        label="Exact + Contract built from verified request",
    ),
)

# Serialize
print(contract.to_json(indent=2))
```

```python
from reasoning_kernel import (compute_contract_digest, compute_precondition_digest,
```

§VII. Cross-Field Invariants #cross_field_invariants
====================================================================

Enforced by `validate_cross_field_invariants()`:

```python
from reasoning_kernel import validate_cross_field_invariants

errors = validate_cross_field_invariants(contract)
```

Key invariants (see §5.3 for full list):
- CONVERSATION → effect=NO_WRITE, execution=none, budgets=0
- OBSERVE → effect=NO_WRITE, budgets=0, read-only ops
- EXECUTE_TEST → effect in {NO_WRITE, DECLARED_TEMP_WRITE}
- MODIFY → effect=PERSISTENT_WRITE, approval required+approved
- ELEVATED → approval required
- DESTRUCTIVE → not REVERSIBLE
- PERSISTENT_WRITE → rollback in {RESTORE, COMPENSATE} or risk=DESTRUCTIVE

§VIII. Resource Identity & Containment #resource_identity
====================================================================

**Path ≠ Identity (§6.1).** A canonical path identifies a location, not an object.
Existing targets MUST be bound to stable identity:

| Resource Type | Identity Proof |
|---------------|---------------|
| File/Directory | device + inode, Windows file ID, content hash, size |
| Git ref | repo identity + ref name + object ID |
| Database row | DB identity + table + primary key + row version |
| Cloud object | account + region + resource ID + version/ETag |
| Process | PID + start time |

```python
from reasoning_kernel import Resource, ResourceIdentity

resource = Resource(
    id="target_file",
    kind="file",
    canonical_locator="/project/src/main.py",
    boundary="/project/src",
    existence_precondition="must_exist",
    identity=ResourceIdentity(
        device="0x80000000", inode=12345,
        content_hash="sha256:abc123...",
        size=2048,
    ),
    descendant_policy="none",
    wildcard_policy="reject",
    link_policy="reject",
)
```

**Before execution:** Resolve path → inspect symlinks/junctions/mounts → confirm identity
→ record preconditions → immediately before mutation, restat and compare.
Mismatch = PRECONDITION_MISMATCH → stop, create new revision.

§IX. Effects, Budgets, Atomicity #effects #budgets
====================================================================

Every intended effect is declared as an `AllowedEffect` with concrete numeric bounds:
```python
from reasoning_kernel import AllowedEffect, Budget

effect = AllowedEffect(
    resource_id="target_file",
    operation="replace",
    maximum_objects=1,
    maximum_bytes_written=4096,
    atomic_group="schema_migration",  # part of an atomic transaction
)

budget = Budget(
    maximum_created=0,
    maximum_modified=1,
    maximum_deleted=0,
    maximum_bytes_written=4096,
)
```

**Prohibited:** Strings like "declared_limit", "reasonable", "as needed". All budgets
must be concrete integers.

**Atomic Groups (§7.3):** Multiple effects MAY be one approved transaction WHEN
splitting creates an invalid intermediate state. Must name the group, list all
members, define all-or-none semantics, and explain inseparability.

§X. Rollback & Compensation #rollback
====================================================================

Three modes, defined in `RollbackPlan`:
- **RESTORE**: Recreate exact pre-state from captured artifacts.
- **COMPENSATE**: Apply declared mitigation (not exact restore).
- **NONE**: No verified recovery path (requires DESTRUCTIVE classification).

```python
from reasoning_kernel import RollbackPlan

rollback = RollbackPlan(
    mode="RESTORE",
    trigger_conditions=["verification_failed", "partial_execution"],
    concurrency_guard="current_state_matches_failed_state",
)
```

**Concurrency guard:** Rollback MUST NOT overwrite a resource that changed
independently after the failed operation. Verify before restoring.

§XIV. Bug Fix Protocol #bug_fix_protocol
====================================================================

Formal 4-step chain that prevents LLM hallucination damage during bug fixes.
Implemented as `BugFixProtocol` in `reasoning_kernel.py`:

```python
from reasoning_kernel import BugFixProtocol

protocol = BugFixProtocol("Memory leak in connection pool")

# Step 1: Error test that exactly reproduces the bug (must FAIL)
protocol.create_error_test(lambda: reproduce_leak())

# Step 2: Trial fix (must pass error test, can be dirty/quicky)
protocol.create_trial_fix(lambda: apply_trial_patch())

# Step 3: Real fix (must still pass error test)
protocol.create_real_fix(lambda: apply_real_patch())

# Step 4: Verify against full test suite
protocol.verify(lambda: run_all_tests())
```

```python
        "behavior": "Do not retry unless idempotency and current state are verified",
    },
}
```

§XVII. Conformance Tests #conformance

An implementation MUST pass all tests in the conformance suite.
Tests are defined as executable `ConformanceTest` objects in `reasoning_kernel.py`:

```python
from reasoning_kernel import build_conformance_suite, ConformanceTest

# Build the full 20-test suite
suite = build_conformance_suite()

# Run all tests
all_pass = True
for test in suite:
    result = test.execute()
    status = "PASS" if result else "FAIL"
    print(f"  [{status}] {test.name}: {test.description}")
    if not result:
        all_pass = False

assert all_pass, "Conformance suite must pass"

# Individual test access
test = next(t for t in suite if t.name == "digest_determinism")
assert test.execute() is True, "Contract digest must be deterministic"
```

§XVIII. Reference Validation #validation
====================================================================

The full validation pipeline is defined as executable Python in `reasoning_kernel.py`:

```python
from reasoning_kernel import (validate_for_execution, validate_cross_field_invariants,
                               compute_contract_digest, compute_precondition_digest,
                               ExecutionContract, ApprovalState, InvariantError,
                               ContractStateMachine, ContractState)

def pre_flight_check(contract: ExecutionContract) -> None:
    """Full pre-flight validation before any execution."""

    # 1. Cross-field invariants
    errors = validate_cross_field_invariants(contract)
    if errors:
        raise InvariantError(f"Blocked: {', '.join(errors)}")

    # 2. State machine — must be FROZEN or APPROVED
    state_machine = ContractStateMachine(contract)
    if contract.state not in ("FROZEN", "APPROVED"):
        raise InvariantError(f"Contract must be FROZEN/APPROVED, got {contract.state}")

    # 3. Approval binding
    if contract.classification.activity == "MODIFY":
        digest = compute_contract_digest(contract)
        if contract.approval.contract_digest != digest:
            raise InvariantError("Stale approval: contract digest changed")

    # 4. Resource identity verification
    for resource in contract.resources:
        if resource.existence_precondition == "must_exist" and not resource.identity.file_id:
            raise InvariantError(f"Resource '{resource.id}' missing identity binding")

    # 5. Budget viability
    write_count = sum(
        1 for ae in contract.allowed_effects
        if ae.operation in ("create", "write", "replace", "delete")
    )
    if write_count > contract.change_budget.maximum_created + contract.change_budget.maximum_modified:
        raise InvariantError("Declared effects exceed change budget")

    # All checks passed
    print(f"Pre-flight OK: {contract.contract_id} r{contract.revision}")
```

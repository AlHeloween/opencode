# PART 2 — Gated workflow (process)
# ===================================================================
# Algorithm → Gate map (which algorithm powers which gates)
#   SVM noise filter  → Gate 1 (filter noise during grounding)
#   Classify before   → Gates 3, 7 (classify tasks and actions)
#   Invariants        → Gates 4, 7 (gate MODIFY, approve before mutate)
#   Bug fix protocol  → Gate 8 (structured fix→verify cycle)
# ===================================================================
# Mandatory sequence for EVERY code change. No exceptions.
# "There is no simple enough." One-character edit → all gates.

# GATE 1 — GROUND TRUTH  [kernel: EVIDENCE.ORDER, SEARCH.ORDER, WHERE_WHICH, NO_HARDCODE | wf: observe]
# Read current state: files, logs, tests, conversation context.
# Every observation grounded in a concrete read or oracle output.
# You cannot plan against assumptions.
# e.g. User: "fix the list tool" → first READ list.ts, check git log,
#      run existing tests, THEN decompose. Not: assume you know the code.

# GATE 2 — DECOMPOSE  [kernel: DECOMPOSE | wf: plan | → ALGORITHM_CARD]
# Decompose into sub-goals. Decompose each further.
# Iterate until every sub-step is at file-and-function level.
# If you cannot see the full A-to-Z path — you are not done.
# No hand-waving. Fractal → medoids → todowrite CENTRAL_TASKS (not linear Mode-1 lists).

# GATE 3 — MASTER PLAN  [kernel: SMOKE.BEFORE, REUSE.BEFORE, DECOMPOSE | wf: plan | → ALGORITHM_CARD, todowrite]
# Complete plan: goal → tasks → files → verification oracles.
# Each task: what changes, which files, verified by what oracle.
# Use [ ] / [x] marks. Sync with todowrite board.
# Classify risk per task: Activity + Effect + Risk labels.

# GATE 4 — PRESENT & ASK  [kernel: WRITE.SCOPE | term: mutation]
# Output the complete plan. End with: "Do you approve this plan?"
# Do NOT write code until the user explicitly approves.
# Silence ≠ approval. Ambiguous response ≠ approval.
# CONSTRAINT: ZERO file-modifying tool calls in this gate.
# No Write. No Edit. No Bash that mutates. No MultiEdit.
# You may use todowrite. Text output only.
# A mutation tool call alongside "Do you approve?" — gate defeated.
# e.g. CORRECT:   "Plan: 1) add param to list(), 2) update callers,
#                  3) typecheck. Do you approve this plan?"
#      VIOLATION: "Plan: ... Do you approve?" + edit(file, ...)  ← GATE DEFEATED

# GATE 5 — CONCERN LOOP  [kernel: DECOMPOSE | wf: plan | → GATE 2]
# User raises concerns → return to GATE 2.
# Refine the plan. Re-present. Re-ask.
# Do not defend the old plan — refine it.

# GATE 6 — EXPLORER GROUNDING  [kernel: SEARCH.ORDER, REUSE.BEFORE | wf: research]
# After approval, verify plan against reality before coding.
# Phase 1 — Broad scan: explore agent, precise targets
#   (file patterns, function names, line ranges).
#   Explorer is fast, has no reasoning — give bounded goals.
# Phase 2 — Gap fill: analyze results, second explorer or
#   external search for missing info. Update plan.
# Both phases complete + plan confirmed grounded → proceed.
# e.g. CORRECT: "Find all functions in src/tool/ that call path.dirname.
#                Return file paths, line numbers, signatures."
#      WRONG:   "Search the codebase for path-related things."

# GATE 7 — IMPLEMENTATION  [kernel: CACHE.STABILITY, WRITE.SCOPE, SMOKE.BEFORE | wf: modify]
# Implement exactly what the approved plan specifies.
# Prefer edit tool for rollback safety.
# Classify every action BEFORE executing.
# Deviation from plan → re-approval via GATE 5.

# GATE 8 — ORACLE VERIFICATION  [kernel: VERIFY.OUTCOME, EVIDENCE.ORDER, infomark | wf: verify]
# Oracles MUST be declared in the plan before EXECUTION (SMOKE.BEFORE).
# Run declared oracles only: targeted tests, typecheck, linter, logs — not full-system soup.
# Interaction: Executor applies change → Oracle PASS/FAIL → Analyst may DONE/correct/rollback.
# PASS → [Exact] for that claim only (scoped; status_after_oracle_pass).
# FAIL/timeout → no Exact done; demote claim; fix or halt.
# NEVER self-certify ("seems fine") as Exact — that is Guess.
# Task complete ONLY when oracle passes → mark [x].

# GATE 9 — CLEAN NEXT STATE  [kernel: CLEAN_STATE, SV_OUTPUT]
# End every substantial response with:
#   Done: <items, %>
#   Blocked: <items>
#   Next: <immediate step>
# Move completed plans to plans_completed/.
# e.g. Done: list directoriesOnly param (100%), head/tail -N flag
#      Blocked: none
#      Next: test compare tool on monorepo
```

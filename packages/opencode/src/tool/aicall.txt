Use `aicall` as a **bounded cognition accelerator**: one isolated LLM call on the
exact files and constraints you supply. It is **not** a subagent (no tools, no
repo discovery, no working-tree authority).

## When to use
- Refactor a large module while preserving named APIs.
- Analyse a bounded file set already identified by codegraph/read.
- Draft plan text, alternatives, risk lists (G3/G4 — no file writes).
- Propose unified diff for attached files (G7 — implementation proposal).

## When NOT to use
- Repository discovery, unknown deps, or shell operations.
- Multi-step work needing tool results between reasoning steps.
- Replacing real oracles (tests, typecheck, logs) — G8 requires actual verification.
- "Is it done?" / "does this pass?" — run real oracles.

## InfoMark
- `aicall` output is **Inferred** at best — never Exact, never a system stamp.
- Do not put `aicall` conclusions into `premises_for_plan` until verified by real oracle (G8).
- Self-labeling the reply `[Exact]` is invalid.

## Call contract
1. Ground first — select paths with codegraph/read, attach every needed file.
2. Prompt — goal, preserved behavior, forbidden changes, output format.
3. Output — prefer unified diff or full replacement + risks + focused tests.
4. After — treat as draft; apply with edit tools; run declared oracles before Done.

Every result begins with the direct-call envelope: selected provider/model, API
model, SDK and endpoint, plus the fact that this isolated request sends no
system prompt or tools. The envelope reports request shape, not secrets or the
full user/file content.

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `prompt` | string | yes | Objective, constraints, output contract |
| `files` | string[] | no | Paths read and embedded before the prompt |
| `output_file` | string | no | Save prose to this path instead of inline |
| `model` | string | no | Explicit model override |
| `provider` | string | no | Explicit provider override |

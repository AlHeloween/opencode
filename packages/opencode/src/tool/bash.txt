Executes a bash command as a **non-blocking background job** by default. Use `job_output` to read output, `job_wait` to wait for completion, or `job_kill` to stop the job. For quick synchronous commands (e.g., `echo`, `git status`), set `run_in_background: false`.

Be aware: OS: ${os}, Shell: ${shell}

All commands run in the current working directory by default. Use the `workdir` parameter if you need to run a command in a different directory. AVOID using `cd <directory> && <command>` patterns - use `workdir` instead.

IMPORTANT: This tool is for terminal operations like git, npm, docker, etc. DO NOT use it for file operations (reading, writing, editing, searching, finding files) - use the specialized tools for this instead.

## Background Jobs

Commands run as background jobs. The tool returns immediately with a job ID (e.g., `bash-1`). You then:

1. **Read output incrementally:** `job_output { job_id: "bash-1" }` — returns new text + status (`running`, `stalled`, `done`, `failed`, `killed`)
2. **Wait for completion:** `job_wait { job_ids: ["bash-1"] }` — blocks until done
3. **Kill a stuck job:** `job_kill { job_id: "bash-1" }` — use when status is `stalled` (no output for 15s)

For quick commands where you need the result immediately, opt out of background mode:
```
bash "echo hello" --run_in_background false
```

## Platform Notes

- **Linux**: Bash is the native shell. Use bash syntax (ls, grep, cat, etc.).
- **Windows**: Bash tool is NOT available. Use the `cmd_runner` skill (via `skill` tool) to run interactive commands. `cmd_runner` supports cmd.exe, PowerShell, and can invoke Git Bash if needed.

## Permission Scanning

Commands are parsed with tree-sitter (bash grammar) to detect filesystem-affecting operations (rm, cp, mv, mkdir, write redirections, etc.). The permission system prompts for approval before executing dangerous commands.

## Output Handling

Stdout and stderr are both captured into the tool result. If the output exceeds ${maxLines} lines or ${maxBytes} bytes, it will be truncated and the full output will be written to a file. You can use Read with offset/limit to read specific sections or Grep to search the full content. Do NOT use `head`, `tail`, or other truncation commands to limit output; the full output will already be captured to a file for more precise searching.

**TypeScript / compilers:** prefer `2>&1` so diagnostics are on the same stream as stdout when piping or when a later step parses the text (missing merge can leave errors only on stderr and crash parsers that only consume stdout). Never strip intentional `2>&1`.

## Timeout

The default timeout is 60000ms (1 minute). You can specify an optional timeout in milliseconds. The timeout can also be overridden via the `OPENCODE_EXPERIMENTAL_BASH_DEFAULT_TIMEOUT_MS` environment variable.

**Timeout behavior:** When the timeout is exceeded, the job is killed (tree kill — all child processes). Its status becomes `killed` and any output produced before termination is preserved. Stalled jobs (no output for 15s) are NOT auto-killed — you must explicitly call `job_kill` if you want to stop a stalled job.

Before executing the command, please follow these steps:

1. Directory Verification:
   - If the command will create new directories or files, first use `ls` to verify the parent directory exists and is the correct location
   - For example, before running "mkdir foo/bar", first use `ls foo` to check that "foo" exists and is the intended parent directory

2. Command Execution:
   - Always quote file paths that contain spaces with double quotes (e.g., rm "path with spaces/file.txt")
   - Examples of proper quoting:
     - mkdir "/Users/name/My Documents" (correct)
     - mkdir /Users/name/My Documents (incorrect - will fail)
     - python "/path/with spaces/script.py" (correct)
     - python /path/with spaces/script.py (incorrect - will fail)
   - After ensuring proper quoting, execute the command.
   - Capture the output of the command.

Usage notes:
  - The command argument is required.
  - You can specify an optional timeout in milliseconds.
  - It is very helpful if you write a clear, concise description of what this command does in 5-10 words.
  - Avoid using this tool with `find`, `grep`, `rg`, `fd`, `cat`, `head`, `tail`, `sed`, or `awk` — use the dedicated tools instead.
  - Chain dependent commands with `&&`.
  - Use `workdir` parameter instead of `cd <directory> && <command>`.
  - DO NOT use newlines to separate commands (newlines are ok in quoted strings).

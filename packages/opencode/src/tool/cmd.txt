Executes a Windows cmd.exe command as a **non-blocking background job** by default. Use `joboutput`, `jobwait`, or `jobkill`. For quick synchronous commands, set `run_in_background: false`.

Be aware: OS: ${os}, Shell: cmd

For interactive, long-running, or complex sessions (PowerShell, Git Bash), use the `cmd_runner` skill. Use `workdir` instead of `cd`.

## Background Jobs

Returns a job ID immediately. Stalled jobs (no output for 15s) are NOT auto-killed — call `jobkill`. Opt out of background mode for quick results:
```
cmd "echo hello" --run_in_background false
```

## Windows Path Quoting

Paths with spaces MUST be double-quoted: `takeown /f "C:\Program Files\app"`.
Do NOT escape quotes with backslashes. Prefer `""` inside a quoted string for literal quotes.

## Permission Scanning

Commands are parsed with a batch grammar. Dangerous filesystem ops prompt for approval.

## What will not run (constitution)

Every command is classified before it executes; these are refused, not warned about:

- **File enumeration — hard block.** `dir`, `type`, `tree`, `Get-ChildItem`/`gci`, `Get-Item`, `Resolve-Path`, and `for`-globs (`for %f in (*) do …`); also `ls`, `cat`, `find`, `fd`, `more`, `busybox` wherever a real unix build exists here. Use `list` / `glob` / `grep` / `read`.
- **History rewrite — hard block.** `git checkout`/`switch`/`restore`, `git reset --hard`, `git stash pop|apply|drop|clear`; mutating `fossil` subcommands (`commit`, `add`, `update`, `merge`, `undo`, `revert`…). Recover WIP with the edit-tool `.bak` or the Fossil snapshot.
- **Destructive — approval first** (refused without it): `del /f /s`, `rmdir /s`, `Remove-Item -Recurse -Force`, `format`, `mkfs`, `dd`, `robocopy /mir|/e`, `xcopy /e`, `DROP TABLE` / `TRUNCATE` / `DELETE`, `git push --force`, `git clean -f`.
- **Crash-prone binaries never run bare.** `cargo`, `rustc`, `clang`, `gcc`, `g++`, `zig`, `dotnet`, `msbuild`, `ninja`, `cmake`, `make`, `go`, `bun` are auto-wrapped into `cmd_runner start -- …`; without `cmd_runner` they are refused.

## Output Handling

Stdout and stderr are captured. Truncated above ${maxLines} lines or ${maxBytes} bytes.
TypeScript/compiler diagnostics often go to stderr — use `2>&1` (never strip it):
`bun run script/build.ts 2>&1`

## Timeout

Default 60000ms. On timeout the job is tree-killed; output before termination is preserved.

Before executing:

1. Quote paths with spaces.
2. Use Windows syntax: `copy`, `move`, `del`, `mkdir`, `takeown`. Never `dir` or `type` — both are blocked as file enumeration; use `list` / `read`.
3. Chain with `&&`. Pipe with `|`. Redirect with `>` and `2>&1`.
4. Use `nul` for the null device. Do not use `grep`, `rg`, `head`, `tail`, `sed`, `awk`.

## Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `command` | string | **required** | The command to execute |
| `timeout` | number | — | Optional timeout in milliseconds |
| `workdir` | string | — | Working directory (instead of `cd`) |
| `description` | string | **required** | Clear, concise description (5-10 words) |
| `run_in_background` | boolean | true | Run as a tracked background job |

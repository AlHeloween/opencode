Computer-use visual oracle — self-built cua-driver (trycua/cua, MIT) as a CLI bridge.

Drive GUI apps and browsers in background sessions: screenshots, UIA tree
inspection, clicks/typing/scroll, browser navigation via CDP. Use as the
SMOKE oracle for TUI/visual/web claims (G8) — `typecheck green` is not a
visual oracle; a screenshot or `verify_state` result is.

**Architecture:** vendored `bin/cua/cua-driver.exe` (discovered via
`Global.Path.bin`). One-shot CLI: `call <tool> <json>` routes through the
local daemon (`cua-driver serve`) — the daemon enforces policy, sessions and
authorization; start it once with `cua serve` (long-running: launch via
cmd_runner start, never bare shell). JSON args are piped via stdin to avoid
PowerShell 5.1 quote stripping.

**Actions:**
- `list-tools` — enumerate all 64 daemon tools (desktop + browser).
- `describe` — full schema of one tool.
- `call` — invoke: tool name + JSON args + optional screenshot output path.
- `serve` — NOT here: start daemon externally (cmd_runner start -- cua serve).

**Key tools (subset):**
- `get_desktop_state` — full-screen capture (true pixels, no downscale).
- `get_accessibility_tree` — processes + visible windows + bounds (cheap).
- `get_window_state` — UIA tree and screenshot of one app (structured elements).
- `verify_state` — deterministic predicate check against one window (best
  for SMOKE assertions).
- `click` / `type_text` / `scroll` / `press_key` / `hotkey` — input
  (PostMessage-based, does not steal focus).
- `launch_app` — wrapper-enforced minimized, inactive start (`start_minimized:true`); background UIA/PostMessage actions remain available.
- Browser suite: `browser_prepare`, `browser_navigate`, `browser_click`,
  `browser_type`, `get_browser_state` — CDP over an exactly-bound tab.
- Page reads: `page` with `action:"get_text"` or `action:"query_dom"` when
  supported by the target's accessibility provider. Do NOT use
  `execute_javascript` for a read: arbitrary scripts are deliberately refused
  outside trusted unrestricted mode, even when the expression looks read-only.

**Hard rules:**
- Daemon must run: start via `cmd_runner start -- cua serve`; kill via
  jobkill. Never `start` the daemon bare-shell (TUI-hang protection).
- For `get_window_state` and `get_desktop_state`, call the tool directly with
  the exact window (or desktop). If no `screenshot_out_file` is supplied, the
  wrapper creates a fresh cache path automatically, reads back the PNG, compares
  its header dimensions with the driver's reply, and attaches the image.
  Supply an explicit NEW path only when a named artifact must remain inspectable.
  The reply states source and attached-image pixel dimensions, target, named
  session, and `capture_id`. A path alone is NOT a model-visible image; a
  text-only model gets no actionable observation. Other tools do not create one.
- For a pixel `click` after a model-visible image, pass `pid` and `x,y` in
  **attached-image** pixels; use `scope:"desktop"` for a desktop image. The
  wrapper fills `capture_id` and (when unambiguous) `window_id` from the latest
  matching image in THIS conversation and validates the target and one-shot ID.
  You may pass both IDs explicitly for reproducibility. Multiple windows for a
  PID or missing/used images require a fresh observation or explicit target;
  NEVER fall back to an unbound pixel click. Element and zoom-addressed clicks
  retain their own rules. A provider-resized preview is NOT an exact coordinate
  source: prefer UIA, DOM or keyboard for tiny targets.
- Driver `drag` and other coordinate gestures do not share `click`'s capture-id
  admission contract; this packet does not certify those actions. Re-observe
  and verify the outcome separately rather than treating a gesture as proof.
- Writes to disk count as PERSISTENT_WRITE — verify the artifact by reading
  it back, not by exit code alone.

**When to use:**
- Visual smoke for TUI changes (dialog renders, list scrolls, footer visible).
- Web/browser assertions (page element state, downloads, dialogs).
- Any claim that needs *looking at* a real window rather than type-checking.

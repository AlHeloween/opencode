Change files by the line addresses `read` printed. One call changes many files at once; nothing is written until every address in every file resolves.

## Shape

The whole call is `{"files": [...]}` — ONE element per file. `filePath` is required on every element. The change is exactly one of `edits` (changes to an existing file) or `content` (create a new file).

```json
{
  "files": [
    { "filePath": "src/a.ts", "edits": [ { "fromHash": "3f19c2ea", "toHash": "9c0be411", "newString": "new lines" } ] },
    { "filePath": "src/b.ts", "edits": [ { "fromHash": "a1b2c3d4", "newString": "one line" }, { "insertAfter": "e5f6a7b8", "newString": "added" } ] },
    { "filePath": "src/new.ts", "content": "a file that does not exist yet\n" }
  ]
}
```

`edits` is always an array, even for one change. Several changes to the SAME file go in the SAME element's `edits` array — never as two `files` elements for one path. `files` is an array; a JSON string that decodes to this array is accepted and its decode is named in the result.

## Entry shapes

Replace lines A..B, both inclusive; `newString` carries every line to keep. Replace one line: omit `toHash`, or pass it equal to `fromHash`. Delete: `newString` is `""`. Insert: `insertAfter` names the line to insert after; `00000000` inserts before line 1 and into an empty file. One entry is a span (`fromHash` plus optional `toHash`) OR an insertion (`insertAfter`), never both.

`newString` is required on every entry and is written exactly as sent. A trailing line break is optional: the last line keeps the replaced span's ending. Other new lines take the file's majority ending. `00000000` is no line and is refused as `fromHash` or `toHash`.

## Addresses

Use the hash `read` printed beside the line you mean. An address pins the file, not the line number: identical lines have different hashes, and CRLF and LF hash alike.

After an edit, take the next addresses from THAT edit's result, never from the earlier `read`: a change moves every address below it and none above. In one call, every entry uses the addresses of the SAME read, so batch several changes to one file into one `edits` array instead of sequential calls. Every entry resolves against the ORIGINAL file: an insertion after line N and a replacement starting at N+1 share no line — the insertion lands before that replacement (and after a replacement ending at N). Several insertions at one point apply in entry order.

A missing file lists similar names.

## Endings and encodings

Line breaks are fitted to the file; send plain `\n`. A file keeps its encoding. Delphi source is saved as UTF-8 with BOM and CRLF; legacy ANSI the same. Any conversion is named in the result. Binary files are refused.

## After the write

The result reports the diff, LSP diagnostics, and the fresh addresses in `read`'s form with two lines of context, then every moved label below the change. Labels above did not move and are not repeated. Like `write`, which also prints an address report, the next edit can address them directly. Undo with `restore`.

## Refusals

Every refusal starts with its key and names the file and entry. Nothing is written when any entry is refused.

| Key | When | What to do |
|---|---|---|
| `[empty-files]` | `files` is empty | Pass at least one `{ filePath, edits }` or `{ filePath, content }` entry |
| `[files-not-array]` | `files` is a string that is not JSON, or decodes to a non-array, or to invalid entries | Pass an array; or a JSON string that decodes to one |
| `[content+edits]` | `content` combined with `edits` in one element | Pass one or the other |
| `[missing-change]` | Neither `edits` nor `content` in an element | Pass addressed `edits`, or `content` to create |
| `[bad-encoding]` | `encoding` is not a code page | Pass the legacy page from `read`, e.g. windows-1251 |
| `[encoding+content]` | `encoding` combined with `content` | Omit `encoding` when creating; it names an existing file's page |
| `[same-file]` | Two `files` elements name the same file | Put all of one file's changes in one element's `edits` |
| `[already-exists]` | `content` for a file that exists | Address its lines with `edits` |
| `[not-found]` | Address names a file that does not exist | Create it with `content`, or fix the path |
| `[is-directory]` | Path is a directory | Address a file inside it |
| `[binary-file]` | File is binary | Inspect with `read` and `hex: true`; `edit` is text only |
| `[undecodable]` | File cannot be decoded | Read with the right `encoding` |
| `[no-change]` | Result is identical to the file | Pass a different `newString` or drop the entry |
| `[not-hex]` | Address is not 8 hex chars | Copy the hash `read` printed |
| `[stale-hash]` | Address is not in this file | Re-read and pass the current hashes |
| `[seed-not-line]` | `00000000` used as `fromHash` or `toHash` | Pass it only as `insertAfter` |
| `[either-or]` | An entry has both or neither of `fromHash` and `insertAfter` | Pass one form: span or insertion |
| `[toHash-on-insert]` | `toHash` with `insertAfter` | Drop `toHash`; an insertion has only `insertAfter` |
| `[inverted]` | `toHash` precedes `fromHash` | Order the span first to last |
| `[overlap]` | Two replacements share an original line, or an insertion sits strictly inside a replaced span | Merge them into one entry, or move the insertion to the span's edge |

## Parameters

| Parameter | Description |
|---|---|
| `files[].filePath` | The file to change. Required on every `files` element. |
| `files[].edits` | The changes to this file — an array; several changes to one file go here. Exactly one of `edits` / `content` per element. |
| `files[].content` | Create a NEW file with this content; refused if it exists. Exactly one of `edits` / `content` per element. |
| `files[].encoding` | Code page of a legacy file, as passed to `read`. |

Change files by the line addresses `read` printed. **MODIFY / PERSISTENT_WRITE / ELEVATED** — read before you edit, state what the change means, run the declared oracle after it.

## One call, every file

```json
{
  "files": [
    { "filePath": "src/a.ts", "edits": [{ "fromHash": "3f19c2ea", "toHash": "9c0be411", "newString": "new lines" }] },
    { "filePath": "src/b.ts", "edits": [{ "insertAfter": "00000000", "newString": "new line 1" }] },
    { "filePath": "src/new.ts", "content": "a file that does not exist yet\n" }
  ]
}
```

One change is a list of one — there is no other form. Each file appears ONCE; several changes to it go in its `edits`.

## The address

`read` prints `470  3f19c2ea: text`. The hash is a chain over the file up to that line, so it pins the FILE, not just a line number. **Use the hash printed beside the line you mean** — the address is the lines themselves.

| You want | entry |
|---|---|
| replace lines A..B | `{ "fromHash": hash of A, "toHash": hash of B, "newString": … }` |
| replace one line A | `{ "fromHash": hash of A, "newString": … }` |
| delete lines A..B | `{ "fromHash": hash of A, "toHash": hash of B, "newString": "" }` |
| insert after line X | `{ "insertAfter": hash of X, "newString": … }` |
| insert before line 1 | `{ "insertAfter": "00000000", "newString": … }` |

- `fromHash`..`toHash` is inclusive: both lines are replaced, and everything between them. `newString` must therefore carry every line you want to KEEP from that span.
- An entry is a replacement (`fromHash`) OR an insertion (`insertAfter`) — never both.
- `newString` is the new lines. A trailing line break is optional: the last line ends as the replaced one did.
- **No address resolves, nothing is written — in any file.** Every entry of every file is checked against the files as you read them before anything is saved. There is no fuzzy match: a stale hash means *read again*.

## Endings and encodings

- Your line breaks are fitted to the file's own; send plain `\n`.
- A file keeps its encoding: UTF-8, UTF-8 with BOM, UTF-16 LE/BE.
- **Delphi** (`.pas .dpr .dpk .inc .dfm .dproj`) is always saved as UTF-8 with BOM + CRLF, the whole file.
- **Legacy ANSI** (not UTF-8, no BOM) is saved as UTF-8 with BOM + CRLF. Pass the same `encoding` you gave `read`; a different page does not resolve.
- Any conversion is NAMED in the result. Binary files are refused.

## After the write

LSP diagnostics per file; the project formatter runs and the file keeps its encoding. The pre-edit bytes are backed up (50 per session) — undo with `restore({ filePath })`.

## Parameters

| Parameter | Description |
|---|---|
| `files[].filePath` | The file to change. |
| `files[].edits` | `[{ fromHash, toHash?, newString }]` or `[{ insertAfter, newString }]` — every change to this file. |
| `files[].content` | Create a NEW file instead; refused if it exists. |
| `files[].encoding` | Code page of a legacy file, as passed to `read` (default: the host's). |

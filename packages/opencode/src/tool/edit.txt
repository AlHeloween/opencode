## Mutation class

`edit` is **MODIFY / PERSISTENT_WRITE / ELEVATED**. Follow kernel G7 (IMPLEMENT) rules: read-before-edit, use product tools, preserve unrelated changes, run oracle after change, mark [x] only on PASS.

Before edit: inspect the target (read/codegraph). State the semantic delta, not only the path. After edit: run **declared** oracle before Done / `[x]`. Prefer edit over write for partial updates (rollback-friendly backups).

## File Backups

Each edit automatically creates a backup of the file's pre-edit content. Backups stored under worktree data backups directory. Max 50 per session; oldest deleted first.

**Undo without git:** use `restore` tool — `restore({ filePath })` for latest bak, `restore({ list: true })` to list.

## Matching: 10-Stage Cascade

1. **SimpleReplacer** — Exact match.
2. **LineEndingNormalizedReplacer** — Match `LF`/`CRLF` variations using source offsets; supports text ending within a line.
3. **LineTrimmedReplacer** — Line-by-line after trimming whitespace.
4. **BlockAnchorReplacer** — Anchor on first/last lines, Levenshtein middle.
5. **WhitespaceNormalizedReplacer** — Normalize whitespace runs.
6. **IndentationFlexibleReplacer** — Strip minimum common indentation.
7. **EscapeNormalizedReplacer** — Unescape `\n`, `\t`, etc.
8. **TrimmedBoundaryReplacer** — Try trimmed version of search block.
9. **ContextAwareReplacer** — Anchor-based with 50% middle-line threshold.
10. **MultiOccurrenceReplacer** — Find all exact matches for `replaceAll`.

If all 10 fail, edit throws error. Multiple matches without `replaceAll` also fails — provide more context.

**The cascade is fuzzy BY DESIGN** — a padded or drifted anchor still applies, and the report does not say which stage matched — so `exact: true` is how a caller says «find it literally or refuse»: it runs the exact match ALONE, and a miss under it fails the call instead of landing near it. Default `false` keeps today's accommodating behaviour.

## Line Endings & Unicode
- Matching accepts `\r\n` and `\n` variations, including mixed-EOL source files. Replacement text uses the file's detected line ending.
- Unicode normalization handles dash/quote/space variants.

## Post-Edit Processing
- LSP diagnostics run on modified file after editing.
- File formatting respects project's configured formatter.
- BOM preserved/detected on UTF-8 files.

## Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `filePath` | string | Absolute path to the file to modify |
| `oldString` | string | The text to replace |
| `newString` | string | Replacement text (must differ from oldString) |
| `exact` | boolean | Require a LITERAL match for `oldString` (default `false`). The matcher is fuzzy by design: this turns the guess off for this call. |
| `from` | number | First line of an ADDRESS-BASED edit (1-based — the numbers `read` prints). Needs `expect`. |
| `to` | number | Last line of an address-based edit, inclusive (defaults to `from`). |
| `expect` | string | The CURRENT text of lines `from`-`to`, exactly as you just read it — REQUIRED with `from`/`to`. The tool refuses if the file no longer holds it: that guard is what makes an address safe against line numbers drifting. The slice is then replaced BY POSITION, so a range that repeats elsewhere in the file still addresses the lines it names. |
| `replaceAll` | boolean (default: false) | Replace all occurrences |

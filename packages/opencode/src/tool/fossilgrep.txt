Fossil in this project is an AUTOMATIC AGENT SNAPSHOT SYSTEM — NOT the project VCS.
It records every file change the agent makes so you can undo/redo/review agent work.
For source control, use GIT — Fossil is a sidecar, not the repository.
Constitution: do not use fossil CLI mutate paths; this tool is for inspection/search of the snapshot timeline.

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `pattern` | string | **required** | POSIX extended regular expression to search for |
| `files` | string[] | — | File paths to search. If omitted, searches all tracked files. |
| `ignoreCase` | boolean | — | Case-insensitive search (default: false) |
| `maxResults` | number | — | Maximum number of version matches to return (default: 50) |
| `once` | boolean | — | Stop after first match per file (default: false) |

Useful Fossil commands for development workflow (faster than git for agent review):

  fossil diff                  # What did the agent change? (unified diff)
  fossil diff --brief          # File list: ADDED/MISSING/EDITED
  fossil timeline -n 20        # Last 20 agent snapshots
  fossil undo                  # Undo last agent action (files + tree)
  fossil revert <file>         # Revert a single file to last snapshot
  fossil revert -r <hash> <f>  # Revert file to specific snapshot
  fossil update <hash>         # Jump whole tree to a specific snapshot
  fossil status                # Current state vs last snapshot
  fossil info                  # Current snapshot hash + metadata

Global index of ALL OpenCode projects (cross-project view):
  fossil all list              # Every project with agent snapshots
  fossil all changes           # Projects with uncommitted agent changes
  fossil all ls --ckout        # All local checkouts across projects
  fossil all info              # Snapshot info for every project

These are READ-ONLY or UNDO operations — safe for development review.
Destructive fossil commands (commit, push, merge, etc.) are hard-blocked by the constitution.

Search functionality:
- fossil grep — search ALL committed versions (current + history)
  Use the pattern parameter to search across the entire file history.
  Fossil's NFA regex engine is safe from ReDoS attacks.
  Results are in reverse chronological order (newest first).

## Comment mode — search the timeline by MEANING

Every snapshot check-in's comment carries the turn's SEMANTIC VECTOR (docs/fossil-snapshot.md §2.0.1):

    auto-snapshot sv:<md5> dominant=<one-line focus> Keywords: topic 0.35, … md5: … prev-md5: …

so the timeline is searchable by MEANING, not only by file content:

- «when did we work on X» → searchComments(repo, "X") over the dominant text
- «which turn changed Y and why» → the result carries the changed files (mlink) beside the dominant
- «find the turn with vector <md5>» → search by the 32-hex md5 itself

Measured on this repo's snapshot.fsl (2026-10-15): 418 check-ins, 203 (48.6%) carry the vector,
215 are bare `auto-snapshot` (undo/redo boundaries and read-only turns write no vector — they
match only by their literal text). Comment text is read from `event.comment` in full (max 734
chars measured); `fossil timeline` output truncates it, so the search reads the column itself.

Read-only: `fossil sql -R <repo>` over `event JOIN blob` — never a repo write. A repo that
cannot be opened is NAMED in the error (an auditable zero, never a silent skip).
Regex dialect: POSIX extended regular expressions (no backreferences, no lookaround, no backtracking — guaranteed O(nm) complexity).

Limitations:
- Only searches files tracked by Fossil (use 'fossil ls' to see tracked files)
- No recursive directory flag (-R is reserved by Fossil for --repository)
- Always includes line numbers in output

Fast content search tool that works with any codebase size. Searches file contents using regular expressions.

This tool uses **ripgrep** with the **Rust regex engine**, which follows extended regex syntax (ERE). This avoids many common regex pitfalls — no backtracking surprises, no ReDoS vulnerabilities, and consistent behavior across platforms.

Use this tool when searching file contents for specific patterns. Use Glob when searching by filename.

## Important: Pattern Syntax

- Use `|` for OR (e.g., `foo|bar`). In Rust regex `\|` is a literal pipe character, not an operator.
- Patterns are passed via `-e` flag, so patterns starting with `-` work correctly.
- No need to double-escape backslashes — `function\s+\w+` is correct as-is.

## Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `pattern` | string | — | Regex pattern to search for in file contents |
| `path` | string | workspace root | Directory to search in |
| `include` | string | — | File glob to filter results (e.g., `*.ts`, `*.{js,jsx}`) |
| `noIgnore` | boolean | false | When true, bypasses .gitignore — searches node_modules, logs, .opencode/data, and other ignored paths |

## Output

Returns **file paths + line numbers + matched text content** sorted by modification time. Each match includes the full line of code where the pattern was found.

## Limits

- Maximum **100 results** with partial notice when some paths are inaccessible.
- Lines exceeding **2000 characters** are truncated with `...`.
- This tool is limited to 100 results and 2000-char line truncation. For counting, aggregation, or full output, prefer `rg` via bash (auto-approved for all safe flags).

Call multiple grep searches in parallel when looking for independent patterns.

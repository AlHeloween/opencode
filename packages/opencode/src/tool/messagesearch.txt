Search or browse conversation history across all sessions in the current project.
Ground conversation facts before judgment. Epistemic ranking: Exact > Inferred > Hypothetical > Guess > Unknown.

## Modes

- **Search mode** (with `query`): FTS5 full-text search over all message content. Results ordered by combined BM25 relevance and epistemic-weighted semantic rank.
- **Browse mode** (no `query`): Returns all user messages chronologically per session, each preceded by its context (the preceding assistant message). No ranking.
- **Spine mode** (`corpus: "summaries"`): the session's own memory, one line per epoch, read from the compaction summaries. Each line carries the epoch's **semantic dominant** and its address (`from..to` message ids). This is a table of contents: cheap enough to read in full, and it exists so that the one epoch you need can be opened by ordinal (`{ corpus: "summaries", epoch: N }`) instead of searched for. Two queries replace a word sweep over thousands of indexed parts.

## Search Engine

- **FTS5 full-text search** with Porter stemming and unicode tokenizer over dedicated memory database.
- **Hybrid ranking**: BM25 relevance score (0.7 weight) + epistemic-weighted semantic rank (0.3 weight):
  - `[Exact]` → 10x weight
  - `[Inferred]` → 7x weight
  - `[Hypothetical]` → 4x weight
  - `[Guess]` → 2x weight
  - `[Unknown]` → 1x weight
- Results are ordered by combined rank descending (relevance + confidence).
- Search indexes a separate `memory.db` — main project database is unaffected.

## Output Format

### Browse mode
Results are grouped by session. Each user message is preceded by its preceding assistant response:
```
## Session: abc123
### #4 [assistant]
...previous assistant response...
### #5 [user]
> user query text
```

### Search mode
Results are grouped by session. Each result includes:
- Session ID
- Message index (#N) and part type in brackets: `[text]`, `[tool]`, `[reasoning]`, etc.
- Snippet with query term highlighting (`**term**`)
- Combined rank score with BM25 and epistemic sub-scores

Output is capped at 50KB. Use `sessionread` to get full context around found messages.

**Epistemic ranks:** messagesearch hits are **Inferred** (index snippets). Use `sessionread` for **Exact** ground truth around those IDs.

## Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `query` | string (optional) | — | Search keywords or phrase. Omit to browse all sessions. |
| `limit` | number | 20 | Maximum results to return |
| `corpus` | string | `parts` | `parts` = the indexed transcript (unchanged); `summaries` = the session memory spine |
| `dominant` | string | — | With `summaries`, keep only epochs whose semantic dominant contains this text — searching meaning rather than words |
| `goals` | boolean | false | With `summaries`, also print each epoch's `## Goal` head |
| `epoch` | number | — | With `summaries`, print ONLY that epoch's full body (1-based, in spine order) — the second query |
| `last` | number | — | Keep only the last N units of the selected corpus: epochs for `summaries`, message dominants for `dominants` |
| `range` | string | — | Restrict to a message range in the form the spine prints: `"<fromMessageID>..<toMessageID>"` |
| `dominants` | boolean | false | Descend one level: return the message-level semantic dominants instead of raw parts or snippets |

## When to Use

- Recall prior decisions, bug fixes, or patterns from earlier in the conversation
- Find when a specific file, command, or error was discussed
- Check if a task was already attempted before starting work
- Get context before planning or executing
- Browse all user messages (omit query) to get an overview of past sessions
- **Navigate your own memory**: read the spine (`corpus: "summaries"`), pick an epoch by its dominant, then open that one epoch (`epoch: N`). The spine costs a few kilobytes for a whole long session, where reading the raw window costs tens of thousands of tokens.
- **Descend to the messages**: take the address the spine printed and read it back — `{ corpus: "parts", dominants: true, range: "<from>..<to>" }` returns the messages of that epoch, each with the dominant it carries. Pass the range: without it the same filter scans every message in scope and costs about a second.

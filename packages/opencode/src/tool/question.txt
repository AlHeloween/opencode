Use this tool when you need to ask the user questions during execution. This allows you to:
1. Gather user preferences or requirements
2. Clarify ambiguous instructions
3. Get decisions on implementation choices as you work
4. Offer choices to the user about what direction to take.

## Parameters

The `questions` parameter takes an array of question objects, each with:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `question` | string | Yes | Complete question text |
| `header` | string | Yes | Very short label (max 30 chars) for UI display |
| `options` | array | Yes | Available choices, each with `label` (1-5 word display text) and `description` (explanation) |
| `multiple` | boolean | No | Allow selecting multiple choices (default: false) |

The `custom` field on the question request (not on individual questions) controls whether a "Type your own answer" option is added automatically. When enabled (default), do NOT include "Other" or catch-all options in your question's options list.

## Return Value

Answers are returned as an array of arrays of labels: `ReadonlyArray<ReadonlyArray<string>>` — one inner array per question, each containing the selected option labels. Example:

```
User has answered your questions: "Which approach?"="Option A, Option B", "Proceed?"="Yes". You can now continue...
```

## Tips

- If you recommend a specific option, make it the first option and add "(Recommended)" at the end of the label.
- Keep `header` short — it's displayed as a tab/title in the UI.
- Include clear `description` text for each option to help the user understand the tradeoffs.

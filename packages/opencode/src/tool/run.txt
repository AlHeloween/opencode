Executes a binary directly with arguments — no shell interpretation, no quoting issues.

`run` is **not** a shell: pipelines, globs, and compound commands must use `bash`/`cmd`. Each argument is a separate string — no globbing or quote interpretation. Argument contents are DATA: a multi-line script passed to `-c` is never read as shell commands (measured 2026-10-05).

`cmd_runner send … -- <payload>` is still scanned for brutal destructive actions (`guardBrutalDestructive`). Enumeration inside that TTY is allowed; `rm -rf`, DROP, force-push, git rewrite, and fossil mutate still require approval.

## What will not run (constitution)

The call is classified with `binary` as the first token:

- File enumeration (`ls`, `find`, `cat`, `dir`, `type`, `tree`, `Get-ChildItem`…) is refused the same way it is in the shell tools — use the product tools.
- History rewrite (`git checkout`/`switch`/`restore`, `git reset --hard`, `git stash …`, mutating `fossil`) is refused.
- Brutal destructive (`rm -rf`, `DROP TABLE`, force-push) requires your approval first.
- Crash-prone binaries (`cargo`, `rustc`, `clang`, `gcc`, `g++`, `zig`, `dotnet`, `msbuild`, `ninja`, `cmake`, `make`, `go`, `bun`) are auto-wrapped via `cmd_runner start -- …`; without `cmd_runner` they are refused.

## Binary Resolution

Resolved from PATH. `cmd_runner.exe` and `adm.exe` are allowed on Windows.

## Output Handling

If output exceeds ${maxLines} lines or ${maxBytes} bytes, it is truncated and the full output written to a file. Use Read with offset/limit for sections.

Viewing (all optional, applied in this order): `pattern` — regex, keep only matching lines; `ignoreCase` — case-insensitive `pattern`; `lines` — a 1-based range over what the pattern kept (`"120-180"`, `"120-"`, `"-180"`, `"42"`); `head` / `tail` — first / last N remaining lines (with `head`, the two take a window).

## Timeout

Default 60000ms. `cmd_runner.exe` auto-gets 10 min, `adm.exe` auto-gets 3 min.

## Background Mode

Background job by default (returns job ID). Use `joboutput` / `jobwait` / `jobkill`. Set `run_in_background: false` for quick synchronous execution.

## Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `binary` | string | **required** | The executable to run |
| `args` | string[] | **required** | One string per argument; no shell parsing |
| `workdir` | string | — | Working directory; defaults to the current one |
| `timeout` | number | 60000 | Timeout in milliseconds |
| `description` | string | **required** | What this command does, 5-10 words |
| `run_in_background` | boolean | true | Run as a tracked background job |
| `pattern` | string | — | Regex: keep only matching output lines |
| `ignoreCase` | boolean | false | Case-insensitive `pattern` |
| `lines` | string | — | 1-based range over what the pattern kept |
| `head` | number | — | First N remaining lines |
| `tail` | number | — | Last N remaining lines (with `head`, the two take a window) |

## Examples

```json
{"binary": "python", "args": ["script.py"], "workdir": ".", "description": "Run the script"}
{"binary": "git", "args": ["status", "--short"], "description": "Show working tree status", "run_in_background": false}
{"binary": "node", "args": ["-e", "console.log(1+1)"], "timeout": 5000, "description": "Evaluate an expression"}
```

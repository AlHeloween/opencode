Gates: G9 pre-fold correction of a Layer-1 summary body; structure stays Exact and untouchable.
Principle: why = fix the account before the fold inherits it; NOT to delete failures or add ungrounded facts — replaced text is kept anyway.
Read or correct the prose of a Layer-1 summary before it is folded into `m*`.

A summary has two halves and they do not have the same standing:

- The **body** is Inferred — an account of what happened, written by a model.
  Accounts can be wrong, and a wrong one folded into `m*` is inherited by every
  turn after it. That half is yours to fix.
- The **structure** — `from_id`, `to_id`, `checkpoint_id`, the tool diffs and
  CodeGraph impact — is `Exact — system-computed, not model output`. This tool
  cannot touch it, by construction: the update names one column.

## When to use
- `checkstate` listed an open summary whose body misstates what happened, omits a decision that must survive, or records a refuted claim.
- Before calling `compact`: after the fold the body is in `m*`, and a fix there is a contradiction between two records, not a correction.

## When NOT to use
- To delete an inconvenient record: a failed-work summary is evidence; rewriting it is not a fix, and the replaced text is kept anyway.
- To add ungrounded facts: the body stays Inferred after your edit — editing promotes nothing (@EVIDENCE_ORDER still applies).
- To restate the structure in prose: message ids are already there as Exact handles.

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | string | yes | Checkpoint id from `checkstate` (e.g. `ckpt_…`) |
| `action` | `"read"` \| `"write"` | yes | `read` returns the current body; `write` replaces it |
| `body` | string | for `write` | The corrected prose |
| `sessionId` | string | — | Session to look in. Defaults to the current one. Another session's summaries are readable but not writable. |

The replaced text is kept under `.opencode/data/summary-revisions/` — the
compaction contract is that nothing is lost, and that applies to a correction
exactly as it applies to a fold.

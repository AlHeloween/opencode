Launch a new sub-agent to handle complex, multistep tasks autonomously. The sub-agent runs in an isolated child session with its own conversation context.

## Sub-Agent Types

| Type | Tools Available | Best For |
|------|----------------|----------|
| `explore` | codegraph, read, glob, grep, list, bash, webfetch, universalsearch, messagesearch, session-read | Codebase exploration, file discovery, log searching, prior conversation research |
| `general` | All tools | Planning, design alternatives, root-cause analysis, multi-step implementation strategy |

## Alignment with gates

- **Gate 6** — prefer `explore` with a **bounded** goal (paths, symbols, return shape). Explorer is fast and has weak deep reasoning; vague prompts waste turns.
- **Gate 1** — exploration is OBSERVE; evidence returned is Exact only when tools re-read sources (not explorer prose alone).
- Do **not** use task to skip Gate 4 approval or to mark oracle PASS.
- CORRECT explore prompt: "Find callers of X in src/foo/; return paths, lines, signatures."
- WRONG: "Search for path-related things."

## Child Session Isolation

- **Restricted permissions**: Sub-agents cannot use `todowrite` (managing the parent's plan) or `task` (preventing nested sub-agent spawning).
- **Separate model**: Each sub-agent type uses its own configured model (from `agent.json` or the agent registry) — this means different context windows and costs.
- **Abort propagation**: Aborting the parent automatically aborts the child session.
- **Fresh context**: Each invocation starts fresh unless you provide `task_id` to resume a previous sub-agent session.

## Parallel Execution

Launch multiple sub-agents concurrently by sending multiple Task tool calls in a single message. Independent exploration or analysis tasks should be parallelized for speed.

## Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `subagent_type` | `"explore"` or `"general"` | — | Which sub-agent to launch |
| `description` | string | — | Short (3-5 word) description of the task |
| `prompt` | string | — | Detailed task description for the sub-agent |
| `task_id` | string | — | Resume a previous sub-agent session (continues its context) |

## When to Use

- **explore**: Code structure analysis (codegraph), searching the codebase, finding files, checking logs, gathering evidence before acting. Prefer codegraph over grep for structural questions (where is X defined, what calls Y, impact analysis).
- **general**: Multi-step planning, design discussions, complex analysis, strategy before implementation
- Do NOT use for single trivial operations (read a file, grep a pattern) — those are single tool calls

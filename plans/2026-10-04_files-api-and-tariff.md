## Требования

### 1. Расчёт суммы по фактическому тарифу
- `getUsage` выбирает off-peak/peak по UTC-часу и дню недели.
- Окно и дни — конфиг провайдера, не константа в коде.
- Праздники исключены; нужен список, иначе ложное срабатывание в пике.
- **Инструмент:** уже стоящая тревога дрейфа (`provider/balance.ts`, окно 8, допуск 15%) —
  после правки она обязана замолчать. Любое её срабатывание означает регресс.

### 2. Files API: хранилище с контролем срока
- Загрузка через `POST /files`, `purpose=user_data`, ответ — `file_id`.
- Ответ **не содержит поля состояния** (`id, object, bytes, created_at, filename,
  purpose, expires_at`) — адресуем сразу, ждать нечего.
- Проверка живости через `files.retrieve` перед первой отсылкой.
- Срок: `expires_after` 1 час … 30 дней либо навсегда; **истечение хранится и
  проверяется**, иначе `file_id` протухнет молча.
- Лимиты: 64 MiB на файл, 25 GiB / 10 000 файлов на пользователя, JPEG/PNG/GIF/**WebP**.
- Откат: отказ загрузки → инлайн, с записью в счётчик байтов.

### 3. В ответе — просто вложение
- Ссылка на файл подставляется как вложение в сообщение, а не как текст.
- Содержимое в провод не попадает.

### 4. Кеш устойчивый и не меняется
- Байты префикса не меняются между запросами.
- Вложение адресуется, а не пересобирается.
- Картинки не влияют на префикс, потому что не едут в нём.

### 5. В промпт файлы напрямую не кидаем
- Ни base64 в текстовом блоке, ни data-URI.
- Катастрофический случай зафиксирован: base64 в тексте = ~205 000 токенов против
  ≤1 024 файловым блоком. **Нужен детектор**, логирующий при WARN.

## Раскрыто: `reasoning_content` и как мы строим сообщения

Контракт уже выстроен и измерен — `provider/transform.ts:238-248`,
`provider/gateway/adaptive-client.ts:193`, `provider/gateway/raw-diff.ts:759-810`.

**С инструментами — поле обязательно.** DeepSeek отвечает 400 на assistant-сообщение
с `tool_calls` без `reasoning_content`. Поэтому всегда присутствует, пустая строка —
если CoT не было.

**Без инструментов — поле игнорируется.** Живой замер 2026-08-28: `prompt_tokens`
и prompt-кэш побайтово идентичны с полем и без него. Значит полный CoT в истории
бесплатен, и он сохраняется ради непрерывности рассуждения.

**Порядок канонический:** `reasoning_content` **до** `tool_calls` — мышление
предшествует вызовам, которые оно мотивирует. Финальный ответ без CoT поле
не несёт вовсе.

**Диалект один.** Дублирующие `reasoning` + `reasoning_details` сворачиваются
в нативное `reasoning_content`; тело, уже несущее нативное поле, проходит насквозь
и не пересобирается.

**Следствие для пункта 4:** устойчивость кеша держится именно на том, что CoT
переигрывается дословно из базы. Усечение или перефразирование меняет префикс и
ломает кеш сильнее, чем что-либо другое в сообщении.

**Инцидент, который это зафиксировало:** дампы 2026-09-13 показали 262k ходов с
инструментами, уходивших с `reasoning_content: ""` при полном CoT в базе — тихая
потеря рассуждения. Отсюда `renderIntegrityReport`, который в реальном времени
ловит двойной диалект, отсутствующее поле при `tool_calls`, неверный порядок и
пустое поле на финальном ответе.

## План исполнения

Пять требований раскладываются на пять задач. T2 — единственный блокирующий: без
хранилища файлов T3 адресовать нечем, а T3 — единственный, кто реально убирает
байты из запроса. T1, T4 и T5 независимы и идут параллельно.

### T1 · Тариф, зависящий от времени

| | |
|---|---|
| **Поверхность** | `packages/opencode/src/session/session.ts:617` (`getUsage`) |
| **Суть** | ветка выбора тарифа получает время: UTC-час, день недели, список праздников. Окно и дни — конфиг провайдера, не константа |
| **Сейчас там** | одна ветка на порог контекста и `model.cost`; часов нет вообще |
| **Дым** | 1) 03:00 UTC буднего дня → peak; 2) 03:00 UTC воскресенья → off-peak; 3) 10:00 UTC → off-peak; 4) праздник в окне → off-peak; 5) неизвестный провайдер → текущее поведение без изменений |
| **Оракул** | тревога дрейфа (`provider/balance.ts`) **замолкает**. Любое её срабатывание после T1 — регресс |
| **Откат** | revert одного коммита; `experimentalOver200K` остаётся нетронутым |

### T2 · Хранилище файлов со сроком

| | |
|---|---|
| **Поверхность** | новый `provider/files-api.ts`; таблица в `storage/db.ts` по образцу `balance.sql.ts` |
| **Суть** | `POST /files` (`purpose=user_data`) → `file_id`; хранение `file_id`, `bytes`, `createdAt`, `expiresAt`, `verifiedAt`; проверка живости через `files.retrieve` **до** первой отсылки |
| **Почему срок — обязателен** | `file_id`, протухший молча, даёт запрос, который нельзя диагностировать по логу |
| **Ответа состояния нет** | тело ответа: `id, object, bytes, created_at, filename, purpose, expires_at` — поля статуса нет, ждать нечего, только проверить |
| **Лимиты** | 64 MiB на файл, 25 GiB и 10 000 файлов, JPEG/PNG/GIF/**WebP** |
| **Дым** | 1) загрузка → `file_id` сохранён; 2) `expiresAt` вычислен и переживает перезапуск; 3) протухший `file_id` не отсылается; 4) отказ загрузки → откат на инлайн с записью в счётчик; 5) `files.retrieve` недоступен → файл не считается готовым |
| **Откат** | флаг конфига; выключенный возвращает прежнее поведение целиком |

### T3 · Вложение адресуется, а не вкладывается

| | |
|---|---|
| **Поверхность** | сериализация вложений для DeepSeek в `session/message-v2.ts` |
| **Зависит от** | T2 |
| **Суть** | `{"type":"file","file_id":"…"}` вместо `image_url` с data-URI |
| **Что это даёт** | payload 7.75 MB → ~0.06 MB; снимается риск лимита 48 MiB, к которому мы идём с каждой несвёрнутой картинкой |
| **Чего НЕ даёт** | **денег.** Картинка ≤1024 токена, на тёплом кэше $0.003/M — практически бесплатно |
| **Дым** | 1) на проводе `file_id`, не data-URI; 2) payload упал ниже 0.1 MB; 3) модель видит то же изображение; 4) протухшая ссылка даёт внятную ошибку, а не пустой ответ |

### T4 · Кеш не меняется

| | |
|---|---|
| **Поверхность** | наблюдение: префикс между соседними запросами должен совпадать байтово |
| **Основание** | `transform.ts:244-247` — без инструментов reasoning игнорируется, кэш побайтово идентичен. CoT переигрывается **дословно**; усечение ломает префикс сильнее всего остального |
| **Дым** | 1) два соседних запроса — префикс идентичен до последнего байта; 2) 320 ходов, 251 с CoT и 69 с пустым — обе формы в истории допустимы (hit при этом 99%) |
| **Что ломать нельзя** | переписывание истории задним числом — это и снесло 229 ходов в снятом turn-gate |

### T5 · Файлы в промпт не идут

| | |
|---|---|
| **Поверхность** | приём вложения + `provider/gateway/raw-diff.ts` (`renderIntegrityReport`) |
| **Суть** | детектор `data:image/…;base64,` в текстовом блоке → **WARN**, не `debug` |
| **Почему WARN** | base64 в тексте = ~205 000 токенов против ≤1 024 файловым блоком, разница ×200. При 15 картинках это весь контекст — не оптимизация, а отказ запроса |
| **Почему не debug** | отказ по построению невидим: на успехе тоже не пишется, тишина означала «не вызвали», и это стоило нам дня диагностики |
| **Дым** | 1) нормальный вход не шумит; 2) base64 в тексте поднимает тревогу; 3) вложение файловым блоком тревоги не поднимает |
| **Откат** | флаг конфига |

## Порядок

```
T1 ────────────── независим, даёт эффект сразу, откатается одним коммитом
T5 ────────────── независим, защищает от катастрофы
T2 ──> T3 ─────── блокирующая пара, единственная, что убирает байты
T4 ────────────── наблюдение поверх T3
Т4
 │
 └── T2 ──> T3 ──> T4
```

## Риски

| риск | серьёзность | сдерживание |
|---|---|---|
| T1 берёт неверное окно и **завышает** счёт в тишине | высокая | тревога дрейфа зазвонит в другую сторону; окно и дни в конфиге, не в коде |
| праздники не учтены → ложный пик | средняя | список праздников обязателен, иначе детект молчит об ошибке |
| T3: протухший `file_id` роняет запросы | средняя | проверка перед первой отсылкой, явная ошибка вместо пустого ответа |
| T5: детектор шумит на легитимном контенте | низкая | проверка только по текстовым блокам, не по вложениям |

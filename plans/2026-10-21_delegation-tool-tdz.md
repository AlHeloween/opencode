## The design (three decisions, each with its reason)

1. **Move the lookup, do not defer the read.** The minimal, behaviour-preserving fix is to hoist `const taskRecents` / `const pipeRecents` above the `chainResolved` thunk. The t87 contract — «ONE lookup of ONE key (L4 `globalRecents`) — the gate, not a parent walk» — is preserved verbatim: still exactly one read of one key per call (per step, in the pipeline's loop), still no parent walk. Deferring the read into the thunk instead would move the failure, not remove it: the thunk would then run before the lookup that fills it.
2. **The pipeline lane gets a behaviour test, not a text guard.** The pipeline tool has no test file at all; a source-text order assertion would be a tripwire on the tree's text, not on the behaviour. The new test drives the tool the way the task test drives its sibling, so the defect is caught by execution.
3. **The live leg runs in an isolated stand.** The candidate is launched with its own project data directory (the live session's DB and log dir stay untouched), on a free model, with the owner's API keys removed from the child's environment (the NAMES are listed in the record, never the values) — the same discipline the TUI tests use.

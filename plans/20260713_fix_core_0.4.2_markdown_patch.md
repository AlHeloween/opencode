# Fix: Patch core@0.4.2 markdown rendering at source level

## Problem

core@0.4.2 minified build (installed via bun) has 3 missing markdown fixes
that exist in the 0.4.3 build. The source is on GitHub v0.4.2 tag but the
installed npm package is minified with different internal hashes.

## Approach — prettify first, never search minified

1. **Prettify** the installed `node_modules/@opentui/core/index.js`:
   ```
   npx js-beautify index.js > index.beautified.js
   ```
   Or use `prettier` if available.

2. **Find source patterns** in prettified code using the GitHub source as guide:

   **Fix 1**: Remove streaming guard in `createInitialStyledText()`
   - Source: `if (!this._streaming) return undefined` at Markdown.ts:479
   - Prettified pattern: search for `_streaming` near markdown renderable code

   **Fix 2**: Add heading/list to `shouldRenderSeparately()`
   - Source: line 492-494 in Markdown.ts
   - Prettified pattern: search for `"code","table","blockquote","hr"` string sequence
   - Add: `||"heading"||"list"`

   **Fix 3**: Guard setStyledText in CodeRenderable
   - Source: around Code.ts lines 325-332
   - Prettified pattern: search for `new StyledText` followed by `.setStyledText(`
   - Guard with: `if (!(this._initialStyledText && filetype === "markdown"))`

3. **Apply fixes** to the prettified file at identified positions

4. **Minify back** using the original compression (or just format with standard tooling)

5. **Commit patch**:
   ```
   bun patch --commit 'node_modules/@opentui/core'
   ```

## Verification

- Run opencode TUI, check markdown rendering (headings, bold, inline code)
- Verify no streaming guard prevents inline formatting in static markdown
- `dir patches\@opentui%2Fcore@0.4.2.patch` to confirm patch file created

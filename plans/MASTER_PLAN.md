## How this file is kept true (hand-owned)

**RULE (owner, 2026-09-29, restated 2026-09-30): an SV is mandatory for every subplan, task and link** —
«чтобы было четко ясно, нафига это все и с чем это коррелирует». This file PRINTS them; it never AUTHORS
them. Each entry's vector has exactly one home, and a reader goes there:

| entry | where its vector lives | how a reader gets it |
|---|---|---|
| a plan | its `<!-- intention: from -> to -->` and `<!-- goal_sv: … -->` header | read the plan FILE |
| a task | the `<!-- sv: … -->` tag on its own box | read the plan FILE |
| an in-flight task's distance, state and oracle | the SVM store, key `["svm","task",<plan>,<task>]` | `svm read <plan> <task>` |
| the goal | THIS file's hand-owned head | you are reading it |

**The check.** `masterPlanCoverage(worktree)` — every plan file under `plans/` must be named in the generated
body, and it returns the gaps by name. It is printed by `planstatus` whether it is clean or not, because a
check whose silence cannot be told from its absence is not a check. Its first run found a real gap:
`plans/2026-09-29_bash-tool-single-execution-path.md` sat under `plans/` and was named nowhere.

**The question — asked every turn, in the turn note.** The instrument can check PRESENCE; only the sources can
answer whether this file is still TRUE:

> `map: N un-ticked box(es) across M plan(s) — accounted for in plans/MASTER_PLAN.md, still matching the plan
> file it came from, and STILL TRUE? A box outlives its topic: rewritten, deleted, or carried by a plan
> somebody forgot to move because confirming it meant running one isolated test. Re-ground each box against
> the code before working it, and close it with the evidence when the work is already there.`

Owner, 2026-09-30: «ненавязчиво спрашивать, как непроставленные галки соотносятся с мастер планом, и требовать
сопоставления с исходниками, это также для того чтобы больше охоты оставлять незавершенные планы в планах не
было». It is a QUESTION on purpose: an instruction is satisfied by editing the note's own output, a question can
only be answered from the plan file and the code. And a stale OPEN box is not untidiness but a SIMULATED status
presented as a measured one — the next reader cannot tell it from real work, and pays for a test the previous
agent skipped.

**The renderer.** `svm render` (plan S4) rewrites everything below the marker: the counts, every plan with its
vector read from its own header, every open box with its tag and its manifest, and an explicit MISSING where a
source has none. Two renders in a row are byte-identical — no clock is read, and the plans are sorted. It
REFUSES a file with no marker and a repository with no master plan, because the goal must never be invented.

**Recursion.** `goal (level 0) → plan → task → oracle`: the plan file owns its tasks, their boxes and their
vectors; the SVM store owns direction and distance; this file prints what they say instead of saying it twice.
If a number here disagrees with a plan file, the plan file wins and this file is regenerated.

**Measured 2026-09-30 on an outside reader** (`aicall`, `space-bunny-free`, no frame, no tools, no session —
brief and reply in `experiments/2026-09-30_masterplan-gravity/`): given only the repo root listing and this

# Исследование: TUI вылетает при загрузке длинных сессий

## Проблема
При загрузке длинных сессий (80+ сообщений) TUI иногда вылетает, возвращая пользователя в командную строку. Проблема существовала до исправлений с дедупликацией плагинов.

## Наблюдения
- Вылет происходит не при каждой загрузке
- Чаще вылетает на длинных сессиях (80+ сообщений)
- В логах нет явных ошибок `rejection` или `exception` перед вылетом
- Процесс просто завершается без логирования причины
- На скриншоте видно, что TUI показывает только нижнюю панель, затем исчезает

## Гипотезы

### 1. Обработка сигналов (SIGINT/Ctrl+C)
**Вероятность:** Средняя
- Возможно, где-то при загрузке сессии генерируется сигнал прерывания
- Проверить: обработчики сигналов в `win32.ts`, `app.tsx`
- Исследовать: не триггерит ли загрузка сессии команду `session.interrupt`

### 2. Таймауты при загрузке данных
**Вероятность:** Высокая
- Длинные сессии требуют больше времени на загрузку из БД
- Возможно, где-то есть таймаут, который прерывает процесс
- Проверить: загрузку сообщений сессии, вычисление diff/summary
- Исследовать: `session.summary`, `computeDiff fallback`

### 3. Проблемы с памятью
**Вероятность:** Средняя
- Большие сессии потребляют больше памяти
- Возможно, срабатывает GC или лимиты памяти
- Проверить: использование памяти при загрузке сессий
- Исследовать: `session.processor`, кэширование

### 4. Ошибки рендеринга
**Вероятность:** Низкая
- Возможно, при загрузке большого количества данных TUI не справляется с рендерингом
- Проверить: логи рендеринга, ошибки отрисовки
- Исследовать: `renderer`, `viewport`, `layout`

## План исследования

### Этап 1: Сбор данных
1. Создать тестовую длинную сессию (100+ сообщений)
2. Загрузить её несколько раз, собирая логи
3. Зафиксировать точное время вылета
4. Проверить системные логи Windows на предмет крашей

### Этап 2: Анализ логов
1. Исследовать логи перед вылетом на предмет:
   - Таймаутов (`timeout`, `duration`, `slow`)
   - Проблем с памятью (`memory`, `heap`, `GC`)
   - Сигналов (`SIGINT`, `interrupt`, `abort`)
   - Ошибок рендеринга (`render`, `display`, `viewport`)
2. Сравнить логи успешной и неуспешной загрузки
3. Проверить метрики производительности

### Этап 3: Инструментирование
1. Добавить логирование в критические точки:
   - Начало загрузки сессии
   - Загрузка сообщений из БД
   - Вычисление summary/diff
   - Активация плагинов
   - Рендеринг TUI
2. Добавить метрики времени выполнения
3. Добавить отслеживание использования памяти

### Этап 4: Воспроизведение и отладка
1. Попытаться воспроизвести вылет стабильно
2. Использовать отладчик для поиска точки вылета
3. Проверить обработчики сигналов и прерываний
4. Протестировать на разных размерах сессий

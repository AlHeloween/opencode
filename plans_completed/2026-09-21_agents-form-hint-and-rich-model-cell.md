# /agents: объяснение агента → hint, модельная ячейка → формат пикера

**Статус:** ACTIVE (2026-09-21)
**Владелец:** сессия `ses_f3d5f006dffe0015eRg1pBuKA2`

## 1. Что просит владелец

1. «здесь есть детальное объяснение по агентам, оно должно быть в hint, а не в списке. Hint меняется по мере движения курсора».
2. «сам список … чтобы было так» → эталонная строка:

```
DeepSeek V4.1 Flash  DeepSeek  ⇣0.15 ⇡0.6 ↻0.003 [👁 🧠 🔧] · max
```

## 2. Что в форме сейчас (Exact)

`dialog-agent.tsx:128-180` (`buildOption`):

| колонка | значение |
|---|---|
| title | `agent.name` (+ ` ← active`) |
| description | `agent.description` — то самое длинное объяснение; режется бюджетом колонки (`dialog-select.tsx:589-596`, `Locale.truncate`) |
| footer | `${cell.model} · ${origin} · ${variant} · task: N` — сырой `deepseek/deepseek-flash` |

`DialogSelect` уже умеет ровно то, что просит владелец: `hint?: (option) => string`
(`ui/dialog-select.tsx:46`), вычисляется по подсвеченной строке — «the list says WHERE you
are, the footer says WHAT it does» (`:371-372`), рендерится как
`<b>{title}</b> <muted>{hint}</muted>` (`:515-523`), `wrapMode="word"` — то есть длинный текст
переносится, а не режется.

Бюджет колонок: `MAX_TITLE_WIDTH = 28`, `MAX_FOOTER_WIDTH = 48` (`:552-556`).

## 3. Решение

**Строка** (колонки те же три, но содержимое — как в пикере моделей, `dialog-model.tsx:64-91`):

| колонка | значение |
|---|---|
| title | `agent.name` (+ ` ← active`) — не меняется |
| description | отображаемое имя модели (`deepseek-flash` → `DeepSeek V4.1 Flash`) |
| footer | `<провайдер> <цена> <возможности> · <вариант>` — эталон владельца |

Переиспользуем готовое, не изобретаем: `compactCostLabel`, `capabilityGlyphs`,
`isFreeModel` из `./model-cost` (та же кодировка, что в пикере и статус-строке).

**Hint** (следует за курсором) — сюда переезжает всё, что строка теперь не несёт:

```
<agent name>  детальное объяснение · модель из слоя <origin> · task: N
```

Почему origin и task тоже в hint: в строке они не помещаются (footer 48 при
`provider+cost+caps+variant` ≈ 45), а терять их нельзя — origin отличает собственный
override сессии от унаследованного значения (`agent-model-cell.ts:8-13`), а `task: N` —
число subagent-override'ов. Список остаётся «где я», hint — «что это».

**Пустое состояние не меняется**: если модель не разрешилась ни одним слоем, в description
идёт guard-метка (`inheritLabel(scope)`) — как и раньше, ячейка не бывает пустой.

## 5b. Правки по ходу проверки владельцем (2026-09-21 06:47-06:58Z)

- **«при отрисовке экран дёргается»** — строка hint появлялась только у строк, у которых есть
  что сказать, и панель меняла высоту, когда курсор уходил на «Recently Used Models».
  Исправлено в `ui/dialog-select.tsx`: если диалог запросил hint, линия резервируется на весь
  список (пустая строка — цена устойчивой), текст внутри появляется по курсору.
- **Фикстуры тестов** — владелец: «нет, вот модель для тестов. На hf у нас сейчас денег нету» →
  примеры переведены на `opencode/muse-spark-1.2-free` (OpenCode Zen, реальные нули = Free) и
  синтетический `custom/org/Model-BF16` для разбора ref; HuggingFace из фикстур убран.
- **«размазаное, нечеткое»** — это была НЕ эта правка: медиа-элемент, примонтированный до
  ответа терминала, навсегда залипал на символьной ветке. Починено в `media-image.tsx`
  (слушатель `CliRenderEvents.CAPABILITIES` + повторный прогон конвейера), см.
  `plans_completed/2026-09-21_media-image-zero-layout-after-opentui-rebase.md`.
- **Бюджет масштаба (512)** — владелец дважды уточнил: «512 это сторона если вылазит за
  границу, а если нет то не надо … скейлить если больше чем 512 иначе мы получим громоздкие
  вставки что совсем не гуд». Промежуточная правка (бюджет = ширина окна) откачена, 512 на
  сторону восстановлены; в `NATIVE_IMAGE_MAX_PIXELS` записано и обоснование, и то, что
  исходная жалоба на размытие была про символьную ветку, а не про этот потолок.

## 6. Риск

Точный порядок в footer — моя реконструкция эталона владельца (провайдер первым, вариант
последним). Если он хотел иначе — правится одной строкой в помощнике.

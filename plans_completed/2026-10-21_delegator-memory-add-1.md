## The design (three decisions, each with its reason)

1. **The FILE is the source; the authored table is GONE.** The owner's objection was concrete: «A future memory write by the delegator would also need a repo commit.» If the meaning lived in the repo, every write would still need one ⇒ the file's own SV block carries the meaning — its keywords, its dominant, its chain and now its title — and `scripts/memory_authoring.py` is deleted, not parked (a parked second copy pays rent and teaches that two copies are normal). The title was the last meaning the table still owned: the keywords and the dominant were already in the blocks ⇒ it moved in as one `Title:` line, written by a reader, never derived by a script.
2. **The INDEX is the derived copy, and the audit guards it.** One copy of the meaning is the source (the file). The second copy that can exist is `MEMORY.md` — the index the app loads at session start. The audit already compared every index line against the file's title and rule clause; now that comparison runs against the file's OWN `Title:` instead of the table's, so the two cannot disagree — and two fixtures prove the comparison can fail.
3. **`stamp` is a FORM tool, never a meaning tool.** It repairs the canonical name, the metadata, the links and the label fields, and re-renders the block from the file's own values; a file with no block is left alone and REPORTED («the meaning must be written by a reader into the file»). Before this change `stamp` OVERWROTE every block from the table — it was the second writer of the meaning, and the table's reason for existing.
